# 보장분석 랜딩 — 광고가 떨어지는 곳

광고비가 직접 닿는 페이지입니다. CRM 앱과 **따로 배포합니다.**
문구 한 줄을 고쳐도 CRM 앱은 다시 나가지 않습니다.

```
보장분석/
  index.html      페이지 전부 (CSS·JS 안에 들어 있음, 빌드 없음)
  config.js       Supabase 주소와 anon 키 — 배포 전에 채웁니다
  netlify.toml    이 폴더만 배포하는 설정
  README.md       이 파일
```

## 배포 — Netlify 사이트를 하나 더 만든다

1. Netlify → **Add new site** → 같은 저장소(`apex-crm`)를 고릅니다
2. **Base directory** 에 `보장분석` 을 넣습니다 ← 이것만 하면 됩니다
3. Build command 는 비우고, Publish directory 는 `.`
4. 배포된 주소를 광고 도착지로 씁니다

Base directory 를 잡으면 Netlify 가 `보장분석/netlify.toml` 을 읽고
이 폴더만 게시합니다. CRM 사이트는 그대로 루트를 게시하므로
두 배포가 서로를 건드리지 않습니다.

도메인을 따로 붙이시려면 이 사이트에만 붙이면 됩니다.

## 배포 전에 채울 것

**`config.js`** — Supabase 주소와 anon 키.
채우지 않으면 신청 버튼이 「접수 실패」 안내를 띄웁니다.
조용히 사라지는 것보다 낫기 때문에 일부러 그렇게 두었습니다.

**`index.html` 안의 `SITE`** — 페이지 맨 아래 script 안에 있습니다.

| 값 | 쓰이는 곳 |
|---|---|
| `kakaoUrl` | 하단 카톡 버튼. 비우면 버튼이 안 보입니다 |
| `privacyUrl` | 푸터의 개인정보처리방침 링크 |
| `tel` | 저장이 실패했을 때 안내에 넣는 번호 |

**대괄호 `[ ]` 자리** — 화면에서 붉게 보입니다. 전부 채워야 심의에 올립니다.
목록은 `docs/광고/보장분석_심의제출.md` 에 있습니다.

- 설계사명 · 소속 · 등록번호 · 협회번호 · 사업자번호 · 주소 · 연락처
- 광고심의필 번호와 유효기간
- 개인정보 보유기간 일수
- 상담 사례 두 건의 실제 수치 — **막대의 `data-w` 값도 같이 고쳐야** 그래프가 맞습니다

## 신청이 들어오는 길

```
광고 → 이 페이지 → web_leads (신청함) → 대표가 보고 배정 → dbs (내 DB)
```

표는 `migration_43_web_leads.sql` 이 만듭니다. 아직 안 돌렸다면 먼저 돌리세요.
익명 방문자에게는 **넣기 권한만** 있습니다. 읽기·수정은 대표·본부장만 됩니다.

## 광고 소재를 세는 법

주소 뒤에 utm 을 붙이면 신청과 함께 저장됩니다.

```
https://[주소]/?utm_source=meta&utm_medium=paid_social&utm_campaign=bojang_08&utm_content=03
```

`utm_content` 에 소재 번호를 넣어 두면 어느 소재가 계약까지 갔는지 셀 수 있습니다.
세지 못하면 광고를 줄일 근거도 없습니다.

## 화면에 있는 통계

전부 공공 출처입니다. **숫자를 고치면 바로 아래 출처 줄도 같이 고쳐야 합니다.**

| 숫자 | 출처 |
|---|---|
| 평생 암 발생 확률 남 44.6% · 여 38.2% | 중앙암등록본부 「2023년 국가암등록통계」 |
| 5년 상대생존율 73.7% · 암유병자 273만 명 | 같은 통계 |
| 실손 세대별 비중 (1세대 17.1 / 2세대 41.2 / 3세대 21.6 / 4세대 17.7) | 금융감독원 실손의료보험 사업실적, 2024년 말 계약 기준 |

세대 비중의 합이 97.6% 인 것은 오차가 아니라 나머지 유형입니다.
막대 끝에 「그 외 2.4%」 로 표시해 두었습니다.

통계는 해마다 갱신됩니다. **광고를 다시 돌릴 때 최신판이 나왔는지 확인하세요.**

## 고친 뒤에 돌릴 것

```
node scripts/check-lp.js      # 신청이 사라지지 않는가 · 준법 문구가 남아 있는가
node scripts/check-html.js 보장분석/index.html
```

`check-lp.js` 는 저장소 뿌리에서 돌립니다. 26개를 봅니다 —
고른 항목이 신청서까지 가는지, 동의 없이 자료가 나가지 않는지,
서버가 죽었을 때 화면이 조용하지 않은지, 심의 문구가 지워지지 않았는지.
