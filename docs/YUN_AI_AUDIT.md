# YUN AI AUDIT — AI 기능 통합 전 감사

작성일: 2026-07-19 · 대상: `app/index.html` (단일 파일 SPA) · promptVersion 도입 전 상태 진단

## 1. 감사 목적

앱 전체에 흩어진 AI 호출이 **하나의 윤시현 정체성·판단기준·화법·준법정책**을 공유하는지 점검하고, 통합(YUN CORE) 대상과 리스크를 식별한다.

## 2. AI 호출 지점 인벤토리

| 계층 | 위치 | 공통 프롬프트 | 문제 |
|---|---|---|---|
| 콘텐츠 생성기 (GEN 30+종) | `GEN[]` 각 `build().system=sys(...)` | `sys()` → `getPersona()` | 페르소나가 **"콘텐츠 카피라이터"** 톤에 한정. 판단·준법 기준이 도구마다 제각각 |
| 보장분석 엔진 | `osReasoningPrompt()` (line ~4015) | 자체 판단원칙 9개 인라인 | 철학이 **여기에만** 존재. 다른 도구와 단절 |
| 결과물 리포트 4종 | `osReportPrompt()` (advisor/client_a4/katalk/script) | `sys(...)` | 답변 구조·화법이 문서마다 상이 |
| 의료/인수/고지 도구 | `CLAUDE_ONLY_GEN` 5종 | `sys(...)` | 준법 면책은 있으나 판단 스파인 공유 안 됨 |
| 학습루프 | `osSubmitFeedback()` → `advisor_feedback` → `knowledge_rules` | 분석엔진에만 주입 | 규칙이 분석에만 반영, 다른 도구엔 미적용 |

## 3. 핵심 발견 (Findings)

1. **정체성 분산**: `sys()`의 기본 페르소나(`DEFAULT_PERSONA`)는 마케팅 카피 작성자다. 리스크 분석가 정체성(강점 우선·근거 기반·비단정)이 분석엔진에만 있고 30여 개 생성기에는 없다.
2. **판단 언어 부재**: FACT/해석/제안/확인(VERIFY)을 구분하는 공통 규약이 없다. 사용자는 AI 문장이 사실인지 추정인지 구분 불가.
3. **금지표현 통제 미흡**: 준법 문구는 있으나 "무조건 가입·100% 지급" 등 금지어 리스트가 코드에 상수로 존재하지 않아 도구별 준수가 프롬프트 문장에 의존.
4. **화법 표준 없음**: 고객 유형별(분석형/불안형/가격민감형/위임형/전문가형) 화법 조정 규칙 부재.
5. **버전 추적 불가**: 프롬프트 정책 버전이 없어 "어떤 기준으로 뽑힌 답인지" 사후 추적이 어렵다.

## 4. 통합 대상 (What to unify)

- 단일 `sys()` 진입점이 이미 모든 GEN 도구를 통과 → **여기에 공통 스파인을 주입하면 30+종이 즉시 통일**된다. (최소 변경, 최대 효과)
- 분석엔진·리포트는 `sys()`에 `deepKind` 인자를 추가해 도메인 심화 규칙을 선택 주입.

## 5. 리스크 & 완화

| 리스크 | 완화 |
|---|---|
| 스파인이 길면 Claude 토큰비 증가 | 스파인을 압축(~450 토큰)하고 심화 규칙은 필요한 도구만 |
| 기존 카피 톤 상실 | 페르소나를 **[브랜드 톤] 레이어로 유지**, 스파인은 그 위 상위 정체성으로만 |
| ES5 호환 | 화살표는 단순 콜백만, `?.`/`??` 미사용 |
| 기능 파손 | `sys()` 시그니처 하위호환(2번째 인자 옵션), `npm run check` 14/14 |

## 6. 결론

`sys()`가 이미 유일한 공통 관문이라는 사실이 **통합의 결정적 지렛대**다. `YUN_CORE` 객체 + `yunSpine()`을 `sys()` 앞단에 주입하고, 분석·리포트에 `yunDeep()`를 선택 결합하면 구조를 갈아엎지 않고 전 도구를 하나의 윤시현 기준으로 통일할 수 있다. → `YUN_AI_ARCHITECTURE.md` 참조.
