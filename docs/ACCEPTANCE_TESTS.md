# ACCEPTANCE TESTS — 완료 판정 기준

Claude Code는 아래 테스트를 모두 통과하기 전 “완료”라고 말하지 않는다.

## A. 기존 앱 회귀 테스트

1. `npm run check` 성공.
2. 기존 대시보드·재무설계 iframe·계산기·콘텐츠 생성기가 정상.
3. 기존 PDF 보장분석 4개 메뉴가 깨지지 않음.
4. 카카오톡 인앱 브라우저 호환 규칙 위반 없음.
5. API 키가 소스에 하드코딩되지 않음.

## B. 인증과 권한

1. 관리자·설계사 계정 로그인.
2. 설계사는 본인 고객만 조회.
3. 관리자는 전체 고객과 분석 조회.
4. PDF 저장소는 인증된 사용자만 접근.
5. 감사로그에 조회·수정 기록.
6. service role 키가 프런트에 없음.

## C. PDF 추출

다음 문서 각각으로 테스트한다.

1. 텍스트형 보장분석 PDF.
2. 스캔 이미지형 PDF.
3. 25페이지 초과 PDF.
4. 표가 여러 페이지로 이어지는 PDF.
5. 한 PDF에 여러 피보험자가 있는 문서.
6. 기존계약 PDF 여러 개.
7. 신규 제안 PDF 1~5개.

검증:

- 보험사, 상품명, 보험료, 납입기간, 만기, 갱신 여부 추출.
- 담보명과 금액 추출.
- 페이지 출처 표시.
- 불명확한 값은 null/확인 필요.
- 총 보험료 합계 검증.
- 사람이 수정 후 승인 가능.

## D. 윤시현 판단엔진

1. 강점을 부족보다 먼저 표시.
2. 실손·진단·치료·소득공백·간병·가족보호 순서로 진단.
3. 갱신형, 납입기간, 은퇴 후 부담 경고.
4. 기존 계약의 해지 위험과 재가입 위험 표시.
5. A/B/C안 모두 생성.
6. 유지·보완·보류·감액·전환·재배치·해지후보 분류.
7. 고객 상황이 부족하면 권장금액을 단정하지 않고 질문 반환.
8. 신규안의 단점도 장점과 함께 표시.
9. 근거 없는 숫자 생성 금지.
10. 페이지 출처 없는 숫자는 최종 보고서에 단정 표시 금지.

## E. 전후 비교

예제:

- 기존 보험료 260,000원
- 신규/조정 후 190,000원
- 일부 보장은 강화되나 갱신형 비중 증가

결과는 다음을 모두 보여야 한다.

- 월 70,000원 감소
- 연간 차이
- 남은 총 납입액 차이
- 강화된 담보
- 약화된 담보
- 갱신형 증가 경고
- 해지 전 확인사항
- 고객 선택용 A/B/C

## F. 학습 피드백

1. 윤시현 관리자가 분석 결과 수정.
2. 수정 전/후와 이유 저장.
3. 수정 내용을 규칙 후보로 생성.
4. 관리자 승인 전에는 전체 분석에 적용하지 않음.
5. 승인 후 새 분석에 적용.
6. 규칙 버전과 적용 근거 표시.
7. 개인정보 제거 후 사례 규칙화.

## G. 결과물

1. 설계사용 정밀 리포트.
2. 고객용 A4 1장.
3. 전후 비교표.
4. 카톡 설명문.
5. 상담 스크립트.
6. HTML/PDF 출력.
7. 준법·약관우선 문구.
8. 결과 수정 및 버전 저장.

## H. 실패 처리

- PDF 분석 실패 시 원인과 재시도 방법 표시.
- API 실패 시 중복 과금 방지를 위한 재시도 제어.
- 큰 문서는 청크 처리와 진행률 표시.
- 일부 페이지만 실패해도 성공한 페이지를 보존.
- 분석을 취소할 수 있음.

# v5 추가 완료 기준 — Financial Advisor OS

## 상담 전과정

- 생활·병원비·치료비·소득공백·가족보호·연금·장기요양·상속 8개 통장을 모두 지원.
- 고객 목표에 따라 질문 순서를 자동 분기.
- 연금 부족액과 장기요양 가족부담을 별도 계산.
- 보험료 절감액이 연금·비상자금으로 실제 재배치되는지 보여줌.
- 고객용 결론은 핵심 공백 최대 3개.

## 지급사례

- claims_cases_manifest.json 가져오기.
- 중복 이미지 checksum 감지.
- 지급명세서/입금알림/고객메시지를 검증등급으로 분리.
- 검증등급이 낮은 사례는 외부 리포트 사용 차단.
- 고객동의·개인정보·준법 승인 없으면 홍보 출력 금지.
- ‘동일 지급 보장 아님’ 문구 자동 삽입.
- 보험금과 납입면제를 모두 사후관리 성과로 집계.

## 90일 아카데미

- 주차별 학습·퀴즈·케이스·롤플레이·관리자 점수.
- 신입/보조/전문가/관리자 화면.
- 필수 질문 누락 경고.
- 녹취 기반 AI 피드백.
- 관리자 승인 게이트.
- 인증 점수와 재시험.

## 데이터 신선도

- 연금·세금·장기요양 제도값은 출처·시행일·검수일·버전을 저장.
- 만료된 기준은 계산을 막거나 확인 경고.
- 고객 보고서에 기준일 표시.

# v6 추가 완료 기준 — 통합 OS (15메뉴·5역할·능동비서·100점·계약관리)

## I. 통합 메뉴·역할 (ROLE_PERMISSION)

1. 15메뉴 구조가 렌더되고, 기존 30+ 도구가 모두 새 위치에서 접근 가능(FEATURE_MAP 매핑대로).
2. `visibleTabs(role)`가 역할별로 메뉴를 필터(advisor/team_leader/education_manager/branch_manager/admin).
3. 역할별 첫 화면이 다르게 표시(설계사/지점장/본부장 홈 카드셋).
4. 다른 설계사의 고객·건강정보 접근 차단(RLS).
5. 교육매니저·지점장 신규 역할 지정 후 정상 동작.

## J. 오늘의 AI 비서 (AI_ASSISTANT_RULES)

1. 로그인 시 시간대·역할별 능동 브리핑이 **AI 없이도** 데이터 집계로 표시.
2. 각 항목에 데이터 근거 뱃지와 바로가기.
3. 상담 전/후, 퇴근 전 브리핑이 실제 고객·상담·청구·검수·학습 데이터를 반영.
4. 고객 상담 전 "반드시 물을 질문"이 360 결측 필드에서 생성.

## K. 100점 성장 (ADVISOR_100_SCORE_RULES)

1. 8영역 점수·총점·등급 표시.
2. 각 가감점이 score_evidence로 근거 연결(임의입력만으로 확정되지 않음).
3. 중대한 준법오류 시 상담제한 배지 별도 표시.
4. 지난주 대비 델타·다음 행동·연습문장·재평가일 표시.

## L. 보험해석·계약관리 (INSURANCE_REASONING_RULES)

1. 보험지식사전 20종×4단계 설명 표시.
2. 계약관리 17종 각각의 전/후·보험료·보장·복구가능성·승인단계 표시.
3. 대체납입/자동대출납입/감액완납의 특별 주의문구가 결론 전 노출.
4. 금지표현 필터가 AI 출력에서 작동, 권장표현·면책문구 삽입.
5. 고위험 항목은 approvals 큐로 이동, 미승인 시 고객 발송 차단.

## M. 청구·사후관리 / 지점장 코칭 / 본부장 승인 / 매뉴얼

1. 청구 워크플로우(접수→보완→지급/삭감/부지급)와 aftercare_tasks 생성.
2. 지점장 코칭 대시보드: 팀원 점수·강약점·오늘 코칭 3인 자동추천.
3. 본부장 승인 큐 처리 → knowledge_rules 규칙 축적(버전·근거).
4. 업무매뉴얼 CRUD + 수정일·수정자·변경이력.

## N. 모바일·인앱

1. PC/모바일 반응형(하단탭 또는 사이드바).
2. 카카오톡 인앱브라우저에서 핵심기능(로그인·고객·비서·해석) 동작.
3. 매 슬라이스 후 `node scripts/check.js` 그린 유지.
