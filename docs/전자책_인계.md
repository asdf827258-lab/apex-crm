## 0. 이 세션에서 지킬 것 — 먼저 읽는다

### 🚫 앱 코드에 손대지 않는다

전자책 세션은 **읽기만** 한다. 다음 파일들은 **절대 고치지 않는다.**

```
app/index.html                     ← 2.46MB · 메뉴·화면 전부
app/finance.html                   ← 670KB · 재무설계 계산기
db-crm.html · db-crm-teams.html    ← DB 통합 CRM
ta-script.html
app/상담자료/**                     ← 상담 프레젠테이션
app/재무설계/**
netlify/** · migration_*.sql · scripts/**
```

이유는 하나다. `app/index.html` 은 300만 바이트다. 두 세션이 동시에
건드리면 **나중에 병합되는 쪽이 앞의 것을 소리 없이 되돌린다.** 실제로
겪었다 — 연금 수정이 병합에서 빠져 13,440 조합 중 3,432개(26%)가 음수로
찍혔고, 탭 닫는 `</div>` 하나가 빠져 화면 아홉 개가 갇혔다.

**전자책 세션이 만드는 것은 결과물 파일 하나뿐이다.** 저장소에 커밋할
필요도 없다 — 아티팩트로 내보내면 된다.

### 화면을 보고 싶으면

읽는 것은 얼마든지 해도 된다. 배포본을 브라우저로 직접 열면 된다.

```
https://apex-os-yunpro.netlify.app/app/index.html
```

Playwright 로 열어 캡처해도 된다. 다만 **로그인이 필요한 화면**이 많다.
로그인 없이 열리는 화면만 캡처되고, 나머지는 로그인 관문이 뜬다.
캡처가 필요하면 사용자에게 그 화면을 직접 찍어 달라고 부탁하는 편이
빠르다.

### 준법 — 이건 어겨선 안 된다

- **고객 실명 금지.** 견본은 「홍길동」 을 쓴다.
- **확정 표현 금지.** 수익률·환급률·지급을 단정하지 않는다.
  "예시 금액과 환급률은 미래 수익을 보장하지 않습니다" 를 붙인다.
- **금융소비자보호법** — 설명의무·부당권유 금지. 기존 계약 해지를
  전제로 권유하지 않는다.
- **자료 없는 것을 지어내지 않는다.** 「자료 없음」 으로 비운다.
- **열쇠·토큰을 문서에 넣지 않는다.** `service_role`, API 키, Netlify
  토큰은 전자책에 예시로도 적지 않는다.

## 1. 무엇에 대한 책인가

**APEX YUN PRO** — 한국 보험·재무설계사를 위한 올인원 웹앱.

- 만든 사람 / 주 사용자: **윤시현** (에이플러스에셋 온탑본부 사업단장)
- 쓰는 사람: 본인 + 팀 설계사들
- 주소: `apex-os-yunpro.netlify.app`
- 서버: Supabase (로그인·데이터), Netlify (배포·야간 자동작업)

책의 목적은 **「이 프로그램으로 월 5천 이상 버는 법」** 이다. 기능
설명서가 아니라, **부족한 설계사가 이걸로 어떻게 달라지는가**의 이야기.

## 2. 앞선 세션이 만들어 둔 것

전자책은 이미 한 번 만들어졌다. **그 결과물부터 받아 보고 시작한다.**

```

```

`WebFetch` 로 내용을 읽을 수 있다. 당시 규모:

| | |
|---|---|
| 본문 | 27,870자 |
| 그림 | 102장 |
| 인쇄본 | 134쪽 |
| 파일 | 4.47MB (폰트 내장) |

만든 방식 — **그 세션의 작업 폴더는 사라졌으니 다시 만들어야 한다.**

```
big-src.html  (소스 · /*__FONTS__*/ 자리표시자)
   ↓ build_font.py  (fontTools subset · 5weight · 331KB)
book-final.html  (4.47MB · 폰트 내장 · 인쇄 가능)
```

> ⚠️ `org.py` 가 파이썬 `copy` 모듈을 가로챈다. fontTools subset 은
> 반드시 `build/` 같은 하위 폴더에서 실행할 것(`cwd=WORK`).

### 앞 세션에서 이미 고친 함정 — 반복하지 말 것

- **CSS 클래스 충돌.** `.ba` / `.say` 를 새로 만들었다가 기존 카드 6개와
  인용문 6개를 망가뜨릴 뻔했다. `.bfa` / `.qs` 로 바꿔 해결.
  → **새 클래스는 반드시 기존 것과 겹치는지 먼저 확인한다.**
- **CSS 우선순위.** `.sty-c p`(0,1,1) 가 `.sty-l`(0,1,0) 을 눌러 각 막
  첫 문장이 본문 크기로 나왔다. `.sty-c > .sty-l` 로 해결.
  → 굵은 제목은 브라우저에서 **계산된 스타일을 전수 대조**할 것.
- **중복 id.** `ms-22` 가 둘 있었다.

## 5. 책에 꼭 들어가야 하는 이야기

사용자가 직접 요구한 것들이다.

1. **월 5천 이상 버는 법** — 사용설명서와 첫 장의 시작이 중요하다.
2. **스토리텔링** — 목차와 설명에서부터 이입되게. **부족한 설계사가
   이걸로 어떻게 달라졌는지.**
3. **보험설계사는 왜 다 잘해야 하는가** — 그 답이 14칸 메뉴다.
4. **마인드맵** — 로고에서 펼쳐지는 형태. 보험설계사의 미래 **전/후**.
   빈 칸 없이 알차게. 어디를 어필하고 무엇을 연습할지.
5. **고객을 어떻게 관리하고 성장하는가** — 하루/주/월 루틴으로.
6. **기능은 이미지 + 텍스트**로. 말로만 쓰지 않는다.

## 6. 앱이 서 있으려면 필요한 것 (책의 「처음 켤 때」 장에 쓸 것)

대표가 한 번만 하면 되는 일이다.

1. **서버 준비 SQL** — 홈 맨 위 배너 → 복사 → Supabase SQL Editor → RUN.
   현재 판 **34**. 이걸 안 하면 사업계획서 적용 · 중복 아이디 삭제 ·
   메뉴 구성 서버 저장 · 내 소개 동기화가 안 된다.
2. **메뉴 구성** — SQL 을 돌린 **뒤에**, 구성이 남아 있는 PC 에서
   설정 → 도구 접근 → 저장. 순서를 바꾸면 기본값이 서버를 덮는다.
3. **서버 열쇠 2개** — 홈 배너 「🔑 열쇠 넣기」 가 다섯 걸음으로 안내.
   `ANTHROPIC_API_KEY` · `SUPABASE_SERVICE_ROLE_KEY` 를 Netlify 환경변수에
   넣고 **재배포**. 이게 있어야 새벽 5시 AI 부서 보고 · 새벽 상담 준비 ·
   평일 종가 수집 · 아침 투자 브리핑 · 매월 성과 리포트가 돈다.
