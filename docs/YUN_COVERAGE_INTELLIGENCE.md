# YUN COVERAGE INTELLIGENCE — 윤시현식 보장분석 판단 엔진

## 1. 목적

이 문서는 AI가 보험 PDF를 요약하는 수준을 넘어, 윤시현 본부장의 실제 상담 판단 순서와 결과물을 재현하기 위한 핵심 도메인 명세다.

이 시스템이 지향하는 것은 “보험 가입 추천 엔진”이 아니다.

> 보험을 상품이 아니라 고객의 현금흐름을 지키는 안전장치로 보고, 현재 계약의 강점은 살리고, 실제 공백과 구조적 위험만 찾아, 고객이 스스로 선택할 수 있는 비교자료를 만드는 의사결정 지원 시스템.

AI는 최종 계약 결정을 대신하지 않는다. 모든 분석은 제공 문서와 입력 정보에 근거해야 하며, 불명확한 숫자·약관·지급 조건은 반드시 `확인 필요`로 분리한다.

## 2. 윤시현식 판단의 최상위 원칙

### 2.1 판매보다 분석

- 처음부터 가입 또는 해지를 결론내리지 않는다.
- 기존 계약을 먼저 이해하고, 좋은 보장은 명확히 인정한다.
- 고객에게 “더 가입해야 한다”가 아니라 “무엇이 있고, 무엇이 비었고, 무엇이 겹치는지”를 보여준다.
- 고객이 네이버 쇼핑처럼 금액·보장·조건을 비교하고 선택하게 한다.
- 압박 문구 대신 A/B/C 선택지를 제시한다.

### 2.2 보험의 목적은 현금흐름 방어

보험은 다음 4개의 통장으로 재구성한다.

1. **병원비 통장**: 실손의료비와 실제 병원비 보전
2. **치료비 통장**: 진단 이후 반복 치료·수술·약물·방사선·중환자실 등에 필요한 현금흐름
3. **소득공백 통장**: 일을 쉬는 기간의 생활비, 대출, 고정지출
4. **가족부담 방지 통장**: 사망, 간병, 치매, 재가급여, 가족의 돌봄 시간과 비용

분석은 단순 담보 합계가 아니라 “질병이 발생한 시간 순서대로 언제 어떤 돈이 나오는가”를 본다.

### 2.3 최종 기준은 유지 가능성

- 보험료가 크고 담보가 많은 설계보다, 고객이 끝까지 유지할 수 있는 구조가 우선이다.
- 갱신형 비중, 납입기간, 은퇴 이후 보험료, 납입면제, 총 납입 부담을 함께 본다.
- 기존 보험료 안에서 재배치 가능한지 먼저 검토한다.
- 과도한 보험료는 보장 자체가 아니라 가계 현금흐름을 훼손할 수 있다.

### 2.4 제3의 근거와 숫자

- PDF, 약관, 상품설명서, 증권, 보험사 확인자료 등 근거가 있는 사실만 단정한다.
- AI의 추론은 사실과 분리하여 `해석`으로 표시한다.
- 숫자는 문서 페이지·상품·담보 단위로 출처를 남긴다.
- 합계가 맞지 않으면 임의로 맞추지 말고 불일치 경고를 낸다.

## 3. 분석 순서 — 반드시 이 순서를 지켜라

### STEP 0. 분석 가능성 점검

입력 문서의 종류를 먼저 분류한다.

- 보장분석 리포트
- 보험증권
- 가입설계서
- 상품제안서
- 상품설명서
- 해지환급금 예시표
- 청약서
- 병력/고지 자료
- 진료비/청구 자료
- 기타

문서가 스캔 이미지이거나 글자가 깨진 경우 OCR 또는 페이지 이미지 분석으로 전환한다.

### STEP 1. 사실 추출

사람이 최종 검토할 수 있는 구조화 데이터로 먼저 변환한다.

필수 항목:

- 계약자 / 피보험자 / 수익자
- 보험사 / 상품명 / 증권번호 일부
- 계약상태 / 가입일 / 갱신 여부
- 월 보험료 / 납입기간 / 보장기간
- 해지환급형 / 무해지형 / 순수보장형
- 주계약과 특약
- 담보명 / 가입금액 / 지급 횟수 / 면책·감액 / 갱신 / 보장기간
- 실손 세대와 가입시기
- 납입면제 조건
- 부담보·제외·할증 또는 심사 특이사항
- 문서 페이지 출처
- 확신도
- 확인 필요 항목

### STEP 2. 정규화

보험사마다 다른 담보명을 공통 보장 분류로 매핑한다.

예시:

- 일반암 / 유사암 / 소액암 / 고액암
- 뇌출혈 / 뇌졸중 / 뇌혈관질환
- 급성심근경색 / 허혈성심장질환 / 심혈관질환
- 질병·상해 수술비 / 종수술 / N대수술
- 암 주요치료 / 표적항암 / 면역항암 / 항암약물 / 방사선 / 로봇수술
- 혈전용해 / 혈전제거 / 순환계 시술·수술 / 중환자실
- 입원일당 / 간병인사용일당 / 간호간병통합
- 치매 / 장기요양등급 / 재가급여 / 시설급여
- 질병·상해 후유장해
- 질병사망 / 상해사망 / 정기·종신
- 운전자 / 벌금 / 변호사선임 / 교통사고처리지원
- 배상책임
- 연금 / 저축 / 종신 목적자금

매핑되지 않는 담보는 원문을 보존하고 `미분류`로 남긴다.

### STEP 3. 고객 상황과 연결

다음 입력이 없으면 분석 전에 `필수 질문`으로 반환한다.

- 나이와 성별
- 직업과 월소득
- 월 고정지출
- 배우자·자녀·부양가족
- 대출과 주요 자산
- 은퇴 예상시점
- 현재 건강과 병력
- 보험료 부담 가능 범위
- 가장 걱정되는 위험
- 보험 가입 목적
- 기존 계약을 유지하려는 이유
- 신규 제안의 목적

고객 상황을 모르는 상태에서 권장금액을 확정하지 않는다.

### STEP 4. 현재 보장의 강점 확인

반드시 부족보다 강점을 먼저 기록한다.

- 이미 잘 갖춰진 핵심축
- 오래된 계약의 유리한 조건
- 비갱신형 또는 납입완료가 가까운 계약
- 해지 시 재가입이 어려울 수 있는 계약
- 실손 세대의 유지 가치
- 납입면제, 넓은 질병 범위, 유리한 약관
- 저렴한 보험료 대비 보장 효율

### STEP 5. 공백·중복·구조위험 분석

#### 공백

- 병원비는 있으나 치료과정 자금이 없는가
- 진단비는 있으나 소득공백이 방어되지 않는가
- 암은 충분하지만 뇌·심장 범위가 좁은가
- 간병·재가·장기요양이 비어 있는가
- 가족생활비와 사망보장 목적이 불명확한가
- 운전자·배상책임 등 생활 위험이 빠졌는가

#### 중복

- 같은 원인에서 동시에 지급되지 않는 유사담보
- 보장 범위가 좁은 담보가 여러 건 중복
- 입원일당·수술비의 과도한 중복
- 갱신형 치료비 특약의 다중 중복
- 목적 없는 종신 또는 사망보험의 중복

#### 구조위험

- 갱신형 비중과 예상 보험료 상승
- 30년납 등 장기 납입 부담
- 은퇴 이후 보험료 지속
- 보장기간이 짧거나 특정 나이에 종료
- 면책·감액·횟수 제한
- 보험료 납입면제 부족
- 무해지형 해지손실
- 해지 후 재가입·고지·부담보 위험
- 계약자·피보험자 구조의 문제
- 실제 목적과 상품 기능의 불일치

### STEP 6. 우선순위

일반적인 기본 우선순위는 다음과 같지만 고객 상황에 따라 조정한다.

1. 실손의료비
2. 암 진단비
3. 뇌혈관·허혈성심장 진단비
4. 수술·치료비와 반복 지급 구조
5. 입원·중환자실·간병
6. 치매·장기요양·재가급여
7. 소득공백·후유장해·가족생활비
8. 운전자·배상책임
9. 사망보장 목적 점검
10. 연금·노후 현금흐름

우선순위는 “가입 순서”가 아니라 “분석 순서”다.

### STEP 7. 유지·보류·재배치·보완 분류

각 계약 또는 담보를 다음 상태로 분류한다.

- **유지**: 현재 목적과 고객 상황에 적합
- **유지 후 보완**: 강점은 있으나 공백 보완 필요
- **보류·확인**: 약관·환급금·고지 위험 확인 전 판단 금지
- **감액 검토**: 목적 대비 과도한 보험료 또는 금액
- **전환 검토**: 실손전환, 감액완납 등 대안 검토
- **재배치 검토**: 보험료를 핵심 위험에 재배분
- **해지 후보**: 중복·효율·목적 문제가 있으나 최종 해지는 별도 검증 후
- **신규 보완**: 기존 안에서 해결할 수 없는 공백

`해지 후보`는 절대 자동 실행 또는 단정 표현을 하지 않는다.

### STEP 8. A/B/C 시나리오

항상 하나의 답만 제시하지 않는다.

- **A안 유지보완**: 기존 계약 최대 유지 + 핵심 공백만 최소 보완
- **B안 보험료 재배치**: 목적 약한 계약 또는 특약을 조정해 예산 안에서 구조 개선
- **C안 가족재무 통합**: 소득공백·간병·노후·상속까지 포함한 전체 재설계

각 안에는 다음을 표시한다.

- 월 보험료 전/후
- 총 납입액 또는 납입기간 차이
- 유지 계약
- 조정 후보
- 신규 추가
- 개선되는 보장
- 새로 생기는 단점
- 고지·인수·면책 위험
- 실행 전 확인사항

### STEP 9. 결론 문장

결론은 가입 지시가 아니라 고객 상태를 한 문장으로 정의한다.

예시:

- “보험이 없는 상태가 아니라 반복 치료비와 장기 소득공백 방어가 약한 상태입니다.”
- “보험을 더 많이 가입할 단계가 아니라, 가족 기준으로 보험료의 목적을 다시 세워야 하는 단계입니다.”
- “좋은 보장은 유지하고, 좁은 뇌·심장 범위와 은퇴 후 갱신 부담만 따로 해결하는 것이 우선입니다.”

## 4. 정량 분석 원칙

### 4.1 점수는 보조지표

점수 하나로 보험의 좋고 나쁨을 결론내리지 않는다.

점수는 다음 6개 축으로 나누어 표시한다.

- 보장 범위
- 지급 시점과 반복성
- 보험료 지속 가능성
- 기간·갱신 구조
- 가족 현금흐름 방어
- 문서 신뢰도

각 점수에는 반드시 근거를 붙인다.

### 4.2 권장금액

권장금액은 고객 소득·고정지출·부양가족·자산을 반영해야 한다.

입력이 없으면 범위를 예시로 보여주되 확정하지 않는다.

예시 계산은 다음 변수로 구성한다.

- 치료 시작 목돈
- 예상 소득공백 개월
- 월 고정지출
- 대출상환액
- 가족생활비
- 비상자금
- 기존 유동자산
- 공적급여·회사복지

### 4.3 보험료

다음 지표를 함께 보여준다.

- 현재 월 보험료
- 신규 제안 월 보험료
- 조정 후 월 보험료
- 연간 보험료
- 남은 총 납입 예상액
- 갱신형 별도 표시
- 은퇴 전/후 부담
- 가구소득 대비 보험료 비중

## 5. PDF 분석 원칙

### 5.1 텍스트 추출만 믿지 않는다

현재 앱의 pdf.js 텍스트 추출은 기본 수단이며, 다음 경우 보완한다.

- 스캔 PDF
- 표의 열 순서가 깨지는 PDF
- 25페이지 초과 문서
- 이미지 안에 보장표가 있는 문서
- 여러 피보험자 또는 여러 설계안이 한 PDF에 섞인 문서
- 글꼴 인코딩 문제로 숫자가 깨진 문서

보완 방식:

1. 페이지별 텍스트 추출
2. 페이지별 이미지 렌더링
3. 서버 OCR 또는 멀티모달 문서 분석
4. 페이지 번호와 좌표 보존
5. 문서별 체크섬과 중복 방지
6. 사람이 수정할 수 있는 검수 화면

### 5.2 2단계 AI 파이프라인

PDF 전체를 한 번에 자유형 프롬프트로 분석하지 않는다.

#### 1단계: Extraction

- 문서에서 사실만 JSON으로 추출
- 담보와 금액을 페이지 출처와 함께 저장
- 불명확한 값은 null
- 추론 금지
- 합계 검증

#### 2단계: Reasoning

- 검수된 JSON만 윤시현 판단 엔진에 입력
- 고객 상황과 연결
- 강점·공백·중복·구조위험 분석
- A/B/C 시나리오 생성
- 고객용과 설계사용 결과 분리

### 5.3 출처 추적

모든 주요 숫자에는 다음 출처 객체를 연결한다.

```json
{
  "documentId": "uuid",
  "fileName": "proposal.pdf",
  "page": 12,
  "sourceText": "암진단비 5,000만원",
  "confidence": 0.96
}
```

## 6. 전후 비교 엔진

### 6.1 비교 단위

- 계약 단위
- 담보 단위
- 공통 분류 단위
- 4개 통장 단위
- 월 보험료와 총 납입액
- 갱신형·비갱신형
- 납입기간·보장기간
- 면책·감액·횟수 제한
- 인수 조건과 부담보

### 6.2 결과 상태

각 담보에 다음 상태를 표시한다.

- 유지
- 강화
- 축소
- 삭제 후보
- 신규
- 중복
- 범위 확대
- 범위 축소
- 확인 필요

### 6.3 반드시 보여줄 것

- 단순 가입금액 증가만으로 `개선`이라 표시하지 않는다.
- 범위가 좁아졌는데 금액만 커진 경우 경고한다.
- 보험료가 낮아졌지만 갱신형 비중이 커진 경우 경고한다.
- 납입기간이 길어졌다면 총 납입 부담을 표시한다.
- 기존 계약 해지로 잃는 권리와 재가입 위험을 표시한다.
- 신규 제안의 장점뿐 아니라 단점도 동일한 수준으로 표시한다.

## 8. 윤시현 피드백 학습

“내 지능”은 한 번의 프롬프트로 완성되지 않는다. 수정 내용을 구조화하여 다음 분석에 반영하는 학습 루프를 만든다.

### 8.1 피드백 종류

- 사실 추출 오류
- 담보 분류 오류
- 판단 우선순위 오류
- 표현·상담 톤 수정
- 권장금액 수정
- 유지·해지 판단 수정
- 고객 유형별 예외
- 보험사·상품별 예외

### 8.2 저장 방식

수정 결과를 단순 채팅 이력으로 저장하지 않는다.

```json
{
  "ruleType": "decision",
  "scope": "senior_care",
  "condition": "80세 이상이고 자녀 돌봄 부담이 큰 경우",
  "preferredDecision": "간병일당보다 재가급여와 장기요양 현금흐름을 먼저 검토",
  "rationale": "시설 입소 전 재택 돌봄 기간이 길고 가족 부담이 먼저 발생",
  "createdBy": "윤시현",
  "approved": true,
  "version": 3
}
```

### 8.3 승인

- AI가 자동으로 영구 규칙을 만들지 않는다.
- 윤시현 관리자 승인 후 `활성 규칙`이 된다.
- 규칙 변경 이력을 보존한다.
- 특정 고객 사례를 일반 규칙으로 만들 때 개인정보를 제거한다.

## 9. 준법·안전

- 보험금 지급을 확정하지 않는다.
- 인수 가능성을 확정하지 않는다.
- 가입·해지·감액·전환을 자동 실행하지 않는다.
- 약관과 보험사 심사 기준이 우선임을 표시한다.
- 고객 개인정보는 로그와 URL에 노출하지 않는다.
- 주민등록번호, 전체 증권번호, 건강정보는 최소 저장한다.
- 민감문서 저장 시 접근권한과 삭제정책을 적용한다.
- 모든 고객용 결과에는 준법 검토 안내를 표시한다.
