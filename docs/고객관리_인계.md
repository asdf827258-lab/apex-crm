# 고객 관리 시스템 — 다음 세션 인계

> **목표 한 줄**
> **30일 안에 모든 고객에게 반드시 연락한다.** 그것이 되는지 화면이 대신 세어 주고,
> 안 된 사람을 눈앞에 들이밀고, 연락할 거리까지 쥐여 준다.

---

## 0. 가장 먼저 알아야 할 것 — 새 표를 안 만들어도 된다

조사해 보니 **필요한 자료가 이미 서버에 다 있다.** 지금은 아무도 그걸 세지 않을 뿐이다.

| 이미 있는 것 | 담긴 것 | 어디서 |
|---|---|---|
| `saved_reports (kind='client_meta')` | 고객 한 명당 한 줄 — 팩트파인딩 · 가족 · **다음 할 일** · **접촉 기록** | `var CM=` 부근 (`app/index.html` 약 2,155,700자 지점) |
| `calls` | `db_id · created_by(누가) · call_at(언제) · result · memo · appointment_at` | `arLoad()` 안의 질의 |
| `clients` | `id · advisor_id · name_masked · created_at · consent_status` | 같은 곳 — **팀원별로 이미 갈라져 있다** |
| `NLIVE` (고객에게 전할 뉴스) | 보험·부동산·세금·지원금·경제 다섯 칸 + `nlMsg(i)` 보낼 문구 | `app/index.html` `renderNewsLive` 부근 |

**따라서 준비 SQL 을 새로 돌릴 필요가 없다.** 판 35 그대로 간다.
(만약 「마지막 연락일」 을 서버에 캐시하고 싶어지면 그때 판 36 을 만들되,
먼저 `calls` 로 계산이 되는지부터 확인할 것 — 안 만들고 되면 안 만드는 게 맞다.)

---

## 1. 만들 것 여섯 가지

### ① 마지막 연락일 → D-day

각 고객의 **마지막 연락일**을 이렇게 뽑는다.

```
max(
  calls 에서 그 고객(db_id / client_id)의 가장 최근 call_at,
  client_meta 안 접촉 기록의 가장 최근 날짜
)
```

없으면 `clients.created_at` 을 기준으로 삼되 **「한 번도 연락 안 함」** 으로 따로 표시한다.
0 으로 채우지 말 것 — 「모른다」 와 「안 했다」 는 다르다.

`지난날 = 오늘 − 마지막 연락일` (KST 기준, 날짜만)

### ② 30일 알람

- **30일 넘은 고객을 목록 맨 위**로 몰아 준다
- 메뉴 「고객 365일」 에 **빨간 배지 숫자**
- 홈에도 한 줄 — 「오늘 안에 연락해야 할 분 **N명**」
- 25일차부터 **미리 노랗게** (닥쳐서 몰아치지 않게)

색: 30일 넘음 `#FF9500` (주황) · 임박 `#FFC043` · 여유 `#8B95A1`.
**빨강(`#F04452`)은 아껴 쓴다** — 다 빨가면 아무것도 안 급해 보인다.

### ③ VIP — 월납 100만원 이상

- 월 보험료 합계 **≥ 1,000,000원** 이면 👑 VIP
- 보험료 출처: `client_meta` 안의 보험 목록(상담자료에서 넘어온 `insurances[].monthlyPayment`).
  **`s10Money()` 와 같은 규칙을 쓸 것** — 0 이하·비수치는 「모름」 이지 0 이 아니다
- VIP 는 **30일이 아니라 14일** 주기로 뜨게 (주기는 설정에서 바꿀 수 있게)
- 보험료를 못 읽은 고객은 「확인 필요」 로 따로 모아 준다 — VIP 를 놓치는 게 제일 아프다

### ④ 「오늘 연락함」 한 번

- 고객 줄에 단추 하나. 누르면 `calls` 에 한 줄 (`created_by = 나`, `call_at = 지금`, `result` 고르기)
- 누른 즉시 D-day 가 0 으로, 목록에서 아래로 내려감
- **되돌리기**도 있어야 한다 — 잘못 눌렀는데 못 지우면 기록이 거짓이 된다

### ⑤ TFA 업무관리 — 팀원별로

`renderAiRep()` (`app/index.html` 약 516,670자) 에 한 칸 더한다.

```
팀원        전체   30일 넘음   이번 달 연락   달성률
홍길동       48       6           42          87.5%
김철수       31      12           19          61.3%
```

- 팀원 본인은 자기 것만, 리더는 팀 전체
- 이미 `AR.calls` 에 `created_by` 가 있으니 **사람별로 가르는 것은 이미 된다**
- 달성률 = (전체 − 30일 넘음) / 전체

### ⑥ 연락 거리 — 「고객에게 전할 뉴스」 연결

30일 넘은 고객 줄에서 바로:

- 그 고객에게 맞는 칸의 뉴스를 **한 건 추천** (VIP·자녀 있음 → 세금·지원금, 젊은 층 → 부동산 등)
- `nlMsg(i)` 로 만든 문구를 **바로 복사**
- 고객 이름은 안 넣는다 (「고객님」) — 지금 규칙 그대로

## 2. 반드시 지킬 것

- **고객 실명은 localStorage 에만.** 서버는 `김○○` 마스킹만. 이 약속을 편의 때문에 깨지 않는다
- **「모름」 과 「0」 을 구분한다.** 연락 기록이 없는 것과 연락을 안 한 것은 다르다
- **조용히 세지 않는다.** 제외한 고객이 있으면 몇 명인지 화면에 적는다
- 새 표를 만들 때만 `SETUP_VER` 을 올리고, **앱과 SQL 이 같은 숫자를 보는지** `check-intro` 가 본다

## 3. 점검은 이렇게

`scripts/check-clients.js` 를 넓히거나 `check-crmcare.js` 를 새로 만든다.

- 마지막 연락일이 `calls` 와 `client_meta` 중 **더 최근 것**으로 잡히는가
- 한 번도 연락 안 한 사람이 「0일」 이 아니라 「한 번도 없음」 으로 뜨는가
- 29일 · 30일 · 31일 경계에서 알람이 맞게 켜지는가
- 월납 999,999 / 1,000,000 / 1,000,001 에서 VIP 가 갈리는가
- 보험료를 못 읽은 고객이 VIP 에서 조용히 빠지지 않고 「확인 필요」 로 뜨는가
- 「오늘 연락함」 을 누르면 D-day 가 0 이 되고, 되돌리면 원래대로 오는가
- TFA 달성률이 손으로 센 값과 같은가
- 팀원 것이 남에게 안 보이는가 (리더만 팀 전체)
