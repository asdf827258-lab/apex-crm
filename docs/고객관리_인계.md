# 고객 관리 시스템 — 만들어진 것과 지켜야 할 것

> **목표 한 줄**
> **30일 안에 모든 고객에게 반드시 연락한다.** 그것이 되는지 화면이 대신 세어 주고,
> 안 된 사람을 눈앞에 들이밀고, 연락할 거리까지 쥐여 준다.

이 문서는 원래 「다음 세션에 만들 것」 을 적어 둔 설계서였다.
**지금은 다 만들어졌다.** 그래서 「어떻게 돌아가는가」 와 「왜 그렇게 했는가」 를 적는다.

---

## 0. 새 표는 끝내 만들지 않았다

조사해 보니 **필요한 자료가 이미 서버에 다 있었다.** 아무도 그걸 세지 않았을 뿐이다.

| 이미 있던 것 | 담긴 것 | 어디서 |
|---|---|---|
| `saved_reports (kind='client_meta')` | 고객 한 명당 한 줄 — 팩트파인딩 · 가족 · 다음 할 일 · **접촉 기록** | `var CM=` 부근 |
| `calls` | `db_id · created_by · call_at · result · memo · appointment_at` | `arLoad()` · `ccLoadCalls()` |
| `clients` | `id · advisor_id · name_masked · created_at` | 같은 곳 — 팀원별로 이미 갈라져 있었다 |
| `NLIVE` (고객에게 전할 뉴스) | 보험·부동산·세금·지원금·경제 다섯 칸 + `nlMsg(i)` | `renderNewsLive` 부근 |

**준비 SQL 은 판 35 그대로다.** 새 표를 안 만들고 되는 일이라 안 만들었다.

## 1. 고쳐야 했던 진짜 버그 — 접촉 기록이 안 보이고 있었다

접촉 기록은 적을 때 `{at:'2026-08-19', how:'전화'}` 로 적힌다.
그런데 TFA 업무관리(`arCliCalc` · `arCliRows`)는 **`.d` 를 읽고 있었다.**

```
적는 곳: L.unshift({ at: cmToday(), ... })     ← at
읽는 곳: (''+(tc[j].d||'')).slice(0,10)        ← d   ✗
```

그래서 접촉 기록이 아무리 쌓여도 TFA 에서는 **한 건도 안 잡혔고**,
모든 고객이 「등록 이후 한 번도 안 만난 사람」 으로 세어지고 있었다.
`arTouchLast(m)` 하나로 모아 **`at` 과 `d` 를 둘 다** 보게 고쳤다(옛 줄이 섞여 있을 수 있다).

## 2. 만들어진 것 — 여섯 가지에 셋을 더했다

### ① 마지막 연락일 → D-day  (`ccLastAt` · `ccIdle` · `ccBand`)

```
마지막 연락일 = max(
  client_meta.touch 중 가장 최근 at,
  calls 중 가장 최근 call_at        ← 이름으로 이어 붙인다
)
```

`calls` 는 고객이 아니라 **DB 줄(`db_id`)** 에 붙어 있다. 둘을 잇는 것은 이름뿐이다.
실명은 서버에 없으므로 **가린 모양(`홍*동`)끼리** 견준다 — `osCallsLoad()` 가
한 사람에게 하던 일을 `ccLoadCalls()` 가 목록 전체에 한 번 한다.

한 번도 연락한 적이 없으면 `ccIdle().ever === false` 이고 **등록한 날부터** 센다.
**`0` 으로 채우지 않는다.** 「모른다」 와 「오늘 했다」 는 다르다.

### ② 30일 알람  (`ccBoardHtml` · `ccNavPaint` · `ccHomePaint`)

- 고객 365일 맨 위에 **달성률 판** — 지금 연락해야 함 / 곧 때가 됩니다 / 👑 VIP / 이번 달 연락함
- 메뉴 「고객 365일」 옆에 **주황 배지** (내 고객만 센다 — 남의 고객이 내 배지에 섞이면 안 된다)
- **홈 첫 화면**에도 한 줄 — 「오늘 안에 연락해야 할 분이 N명」
- 주기의 **5/6 지점부터 미리** 노랗게 (30일이면 25일차, 14일이면 12일차)

색: 넘음 `#FF9500` · 임박 `#FFC043` · 여유 `#8B95A1`.
**빨강(`#F04452`)은 안 쓴다** — 다 빨가면 아무것도 안 급해 보인다.

### ③ VIP — 월납 100만원 이상  (`ccMan` · `ccIsVip` · `ccCycle`)

- 보험료 출처는 팩트파인딩의 **「보험료」 칸(`f_ins`, 만원)**
- `ccMoney()` 규칙 — 상담자료 `s10Money()` 와 **같다**. `0` · `-1` · 빈칸 · 글자는 **모두 `null`**
- VIP 는 **14일**, 일반은 **30일** (셋 다 화면에서 바꿀 수 있다 — `apex_cc_cfg`, 이 기기에만)
- **보험료를 못 읽은 고객은 조용히 빠지지 않는다.** 판과 TFA 양쪽에 몇 명인지 적고,
  어디를 채우면 갈리는지까지 적는다. VIP 를 놓치는 게 제일 아프다

### ④ 「오늘 연락함」 한 번  (`ccMark` · `ccUndo`)

- 줄에서 `☎️ 연락함` / `💬 카톡` 한 번 → `client_meta.touch` 에 한 줄, D-day 가 0
- **되돌리기**가 있다. 잘못 눌렀는데 못 지우면 기록이 거짓이 된다
- 되돌리기는 **이 단추가 남긴 오늘 것(`cc:1`)만** 지운다.
  손으로 적어 둔 기록은 절대 못 건드린다

### ⑤ TFA 업무관리 — 팀원별  (`ccTeamRows` · `ccTeamHtml`)

「🎯 30일 고객관리」 칸. 팀원 본인은 자기 것만, 리더는 지금 고른 팀 전체.

```
팀원      고객  30일 넘음  👑VIP  한 번도 없음  이번 달 연락  달성률
홍길동     48       6        3         1            42        87.5%
```

달성률 = (전체 − 주기 넘긴 사람) ÷ 전체. **달성률이 낮은 사람이 위로 온다** — 도와야 할 사람이 먼저.
아래에 「지금 연락해야 할 분들」 이 이름까지 나온다(40명까지, 넘으면 몇 명인지 적는다).

### ⑥ 연락 거리 — 「고객에게 전할 뉴스」 연결  (`ccNewsCat` · `ccNews`)

줄에서 `📰 전할 소식 복사` 한 번이면 그 고객에 맞는 칸의 기사가 `nlMsg()` 문구로 복사된다.

| 고객 | 고르는 칸 |
|---|---|
| VIP 이거나 부동산이 있다 | 세금 |
| 대출이 있다 | 부동산 |
| 교육비가 있다 | 지원금·혜택 |
| 보장 칸이 비었다 | 보험 |
| 그 밖에 | 경제 |

**고객 이름은 안 넣는다**(「고객님」) — 지금 규칙 그대로.

### ⑦ 지금 진행중인 분  (`ccRun` · `ccRunList` · `ccRunHtml`)

「연락 주기」 는 **모두**를 보는 눈이고, 「진행중」 은 **지금 붙어 있는** 사람을 보는 눈이다.
둘은 다르다 — 어제 만난 사람은 주기로는 여유지만 지금 한창 진행중이고,
그 사람을 놓치면 계약이 날아간다. 주기만 세면 그게 안 보인다.

**TFA 의 `arTouch()` 가 DB 쪽에서 쓰는 「진행중(run)」 과 같은 뜻으로 맞췄다.**
두 화면이 같은 사람을 다르게 부르면 안 된다.
계약이 끝난 사람(`계약완료`·`증권전달`)은 진행중이 **아니다.**

| 순서 | 걸리는 조건 | 줄에 뜨는 글 |
|---|---|---|
| ① | 앞으로의 약속이 있다 (`dbs.next_appt` · `calls.appointment_at`) | `약속 2026-08-22 08:30` |
| ② | 다음 할 일이 잡혀 있다 (`client_meta.next`) | `다음 할 일 · 증권 받기 — 7일 지남` |
| ③ | CRM 단계가 도는 중이다 (`TA`·`AP`·`PC`·`CS`) | `CRM 단계 AP` |
| ④ | 가장 최근 통화가 「상담」 이고 45일 안이다 | `상담하고 12일째` |

- **걸린 까닭을 그대로 줄에 적는다** — 까닭이 안 보이면 그 목록을 안 믿는다
- 약속은 **timestamptz** 다. 그대로 자르면 UTC 가 뜨고 밤 약속은 **날짜까지 하루 밀린다**.
  `ccKst()` 로 한국 시각으로 옮긴다
- 한 사람에게 DB 가 둘이면 **멀리 간 단계**를 쓴다 (`ccStageRank`)
- 상담만 해 두고 다음이 안 잡힌 사람은 **오래된 쪽이 위** — 식어 가는 중이라서다
- 단계 칸이 없는 서버(`CC.noStage`)에서는 **단계로는 못 가린다고 화면에 적고** 약속·다음 할 일로만 센다

### ⑧ 3년 관리 규칙 — 「언제」 다음에 「무엇을」  (`CC_PLAN` · `ccTodoList`)

여기까지는 **언제** 연락해야 하는지만 셌다. 그런데 설계사가 막히는 자리는 거기가 아니다.
「30일 지났네」 까지는 화면이 말해 주는데, 막상 전화를 들면 **무슨 말을 해야 할지**가 없다.
계약은 3년, 5년, 10년을 간다 — 그 사이에 할 일은 정해져 있고 사람이 외우고 있을 수 없다.

**기준일** (`ccBase()`) — 위에서부터 찾고 **어느 것을 썼는지 화면에 적는다.**
① 손으로 적은 계약일(`client_meta.since`) → ② `dbs.contracted_at` → ③ `dbs.policy_sent_at` →
④ `clients.created_at`(**추정** — 계약일이 아니다).
추정으로 센 것을 사실처럼 보여 주면 3년치가 통째로 어긋난다. 「기준일 추정」 딱지를 붙인다.

| 언제 | 무엇을 | 제도 |
|---|---|---|
| 2일째 | 계약 감사 인사 · 청약철회 15일 먼저 알리기 | ● |
| 15일째 | 증권 전달 · 보장 다시 한 번 | ● |
| 32일째 | 첫 회 보험료 출금 확인 — 실효가 제일 많이 나는 자리 | |
| 60일째 | 청구하는 법 알려 드리기 | |
| 90일째 | 암 면책 90일 종료 안내 | ● |
| 105일째 | 3개월 점검 · 소개 부탁 (품질보증 지난 뒤라 안전) | ● |
| 180일째 | 반년 점검 | |
| 1년째 | 1주년 · **13회차 유지 확인** | |
| 1.5년째 | 감액기간 끝나는 담보 확인 | |
| 2년째 | 2주년 · 25회차 유지 확인 | |
| 3년째 | **보장 전체 재점검** | |
| 그 뒤 해마다 | N주년 · 해마다 보장 점검 | |

여기에 달력이 정하는 것(`CC_YEARLY`)이 얹힌다 — 연말정산(11/15~12/31) · 계약 기념일(계약한 달).
**생일은 「오늘 챙길 고객」 이 이미 세고 있어서 두 번 띄우지 않는다.**

- **지나간 일정은 알람으로 안 띄운다.** 3년 된 고객을 처음 넣으면 밀린 항목이 열 개씩 쏟아진다.
  그러면 아무것도 안 하게 된다. 지난 것은 타임라인에 회색으로 **접어 둔다** — 지우지는 않는다
- 한 것은 체크한다 (`client_meta.plan = {키: 날짜}`). 그 창만 닫히고 나머지는 그대로다
- 기준일이 **추정이면 계약 기념일은 안 띄운다** — 엉뚱한 달에 축하하면 안 하느니만 못하다
- 「제도」 는 법·약관이 정한 기간이라 못 바꾼다. 나머지는 관리 습관이니 바꿔도 된다
- 규칙마다 **무엇을 하는지(`how`)와 왜 하는지(`why`)** 를 같이 적었다. 까닭이 없으면 아무도 안 한다

### ⑨ 증권에서 월납 가져오기  (`ccScanRows` · `ccScanApply` · `ccScanAfterSave`)

VIP 는 월납 100만원에서 갈리는데, 그 월납(팩트파인딩의 「보험료」 칸)을 손으로 채워야만 했다.
그러니 거의 모든 고객이 「월납을 못 읽었습니다」 로 남는다. 증권은 이미 앱이 읽는다 — 옮겨 오면 된다.

**납입주기를 반드시 본다.** 통합조회 서류의 「보험료」 칸은 주기에 따라 뜻이 다르다 —
**연납 120만원을 월납 120만원으로 세면 없던 VIP 가 생긴다.**

| 서류 | 월납으로 |
|---|---|
| 월납 | 그대로 |
| 3개월납 / 6개월납 / 연납 | ÷3 / ÷6 / ÷12 |
| **일시납 · 전기납** | **「모름」** — 매달 나가는 돈이 아니거나 서류만으로는 알 수 없다 |
| 주기 미기재 | 월납으로 보되 **그렇다고 화면에 적는다** |
| 보험료 미제공(-1) | 「모름」 |

- 보장분석·비포&애프터·비교·카톡설명·제안서를 **고객에게 저장하는 그 순간** 같이 옮겨진다
  (`ccScanAfterSave`). 그 순간이 앱이 그 고객의 보험을 가장 잘 아는 때다
- **이름이 맞을 때만** 옮긴다 (`ccScanMatch`). 견줄 이름이 없으면 「맞다」 가 아니라 「모른다」 다
- **이미 적혀 있으면 안 덮는다** — 손으로 고쳐 둔 값이 증권 한 번에 날아가면 다시는 안 고친다
- 해지·실효 계약은 애초에 안 들어온다 (`insScan` 이 `lapsed` 로 따로 뺀다)
- **상담자료로 보내는 `sdPlanRows()` 도 같은 규칙을 쓴다** — 두 곳이 다르면 고객 앞의 합계가 갈린다
  (다만 저쪽으로 넘기는 「모름」 은 여태처럼 `0` 이다. `s10Money()` 가 0 을 「모름」 으로 받는다)

## 3. 반드시 지킬 것

- **고객 실명은 localStorage 에만.** 서버는 `김○○` 마스킹만. 이 약속을 편의 때문에 깨지 않는다
- **「모름」 과 「0」 을 구분한다.** 연락 기록이 없는 것과 연락을 안 한 것은 다르다
- **조용히 세지 않는다.** 제외한 고객이 있으면 몇 명인지, 왜인지 화면에 적는다
- 새 표를 만들 때만 `SETUP_VER` 을 올리고, 앱과 SQL 이 같은 숫자를 보는지 `check-intro` 가 본다
