# INSURANCE_REASONING_RULES — 보험 해석·판단 규칙 (윤시현식)

최종 갱신: 2026-07-17. `YUN_COVERAGE_INTELLIGENCE.md`를 상위 규칙으로 하고, 계약관리 판단·안전장치를 통합한다. AI extraction/reasoning 및 UI가 이 문서를 단일 근거로 사용한다.

## 1. 대원칙

1. 보험을 "좋음/나쁨"으로 단순 평가하지 않는다.
2. 추출(사실)과 판단(해석/제안)을 분리한다. 미확인 수치는 추측 금지 → `확인 필요 / 약관 필요 / 보험사 확인 필요 / PDF에서 확인 안 됨`.
3. 기존 계약의 강점을 먼저 인정한다.
4. 고객 상황(재무·건강·목표) 없이 권장금액을 확정하지 않는다.
5. 결론은 단일 강요가 아니라 선택지(A/B/C/유지) 비교로 제시한다.
6. 모든 핵심 수치에 **페이지 출처**를 연결한다.

## 2. 해석 순서 (분석 파이프라인)

강점 → 최초 가입목적 → 현재 목적 → 유지가치 → 재가입 위험 → 핵심 공백(최대 3개) → 중복 → 구조적 위험 → 보험사 확인사항 → 선택지(A/B/C/유지) → 전후 비교 → 관리자 검수.

**강점 신호**: 오래된 약관·낮은 보험료·넓은 보장·비갱신·납입완료 임박·실손 유지가치·현재 병력으로 재가입 곤란·납입면제·유리한 인수조건.

## 3. 4~8 통장 모델

핵심 4통장: 병원비 · 치료비 · 소득공백 · 가족부담. v5 확장 8통장: 생활 · 병원비 · 치료비 · 소득공백 · 가족보호 · 연금 · 장기요양 · 상속. (`account_assessments.account` enum과 일치)
각 통장: 현재/필요/부족액 + 충족도(충분/부족/과잉/중복/확인필요) + 출처.

## 4. 선택안 규격 (A/B/C/유지)

- A: 기존계약 최대 유지 + 핵심만 보완
- B: 보험료 재배치
- C: 보장·연금·간병 통합
- D(유지): 변경하지 않고 유지
각 안 표시: 월보험료 · 남은 납입액 · 유지/조정/추가/감소 계약 · 해지환급금 · 장점 · 단점 · 확인사항 · 고객 영향.

## 5. 계약관리 판단모듈 (17종) — 결론 전 확인 필수

배서 · 계약자변경 · 수익자변경 · 납입방법변경 · 주계약감액 · 특약감액 · 특약삭제 · 감액완납 · 연장정기 · 납입유예 · 자동대출납입 · 대체납입 · 중도인출 · 보험계약대출 · 연금전환 · 부활 · 최종해지.

각 항목 제공(→ `policy_change_options`): 의미 · 적용상품 · 변경 전/후 상태 · 월보험료 변화 · 보장금액 변화 · 유지권리 · 상실권리 · 장점 · 단점 · 보험사 확인 · 필요서류 · 복구 가능성 · 고객 설명문장 · 관리자 승인단계.

**특히 주의**:
- 대체납입: 상품별 의미 상이 → 정확한 상품명·약관명칭·적립금 구조 확인 전 결론 금지.
- 자동대출납입: 보험료가 사라지는 게 아니라 **보험계약대출+이자 발생** 명시.
- 감액완납: 상품별 가능여부·변경 후 보장금액·특약 소멸·계약대출·복구 가능성 확인.

## 6. 안전장치 (금지/권장 표현)

**금지**: "무조건 지급/가입됩니다", "반드시 수익", "기존보험은 전부 나쁩니다", "지금 안 하면 큰일".
**권장**: "약관·심사에 따라 달라질 수 있습니다", "현재 확인된 자료 범위에서는…", "보험사 확인이 필요합니다", "기존계약 장점 유지부터 보겠습니다", "세 가지 선택지를 비교하겠습니다", "실행 전 추가 확인이 필요합니다".

**AI 확정 금지**: 보험금 지급 · 인수 · 세금 · 법률효과 · 의료판단 · 미래 수익률 · 해지 유불리. 근거+확인사항 제시, 필요 시 전문가/보험사 안내.

## 7. 승인 대상(고위험 → `approvals`)

기존보험 해지 · 대규모 감액 · 감액완납 · 실손전환 · 고액 종신/연금 · 병력 많은 고객 · 복잡한 인수전략 · 자동대출납입 장기사용 · 계약대출/환급금 문제 · 민원 가능성 · 부지급 이의제기 · 법인·상속·퇴직금. 관리자 미승인 고위험 제안은 고객 발송 금지.

## 8. 학습 루프

윤시현 수정(전/후/이유) → `advisor_feedback` → `rule_candidates` → 관리자 승인 → `knowledge_rules`(버전·active). 신규 분석은 적용 규칙을 **근거·차이점과 함께** 표시하되 자동 확정하지 않는다.
