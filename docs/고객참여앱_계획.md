# 고객도 함께 여는 앱 — 계획 · 가이드

**만들기 전에 정리하는 판입니다.** 「시그널플래너처럼 고객도 같이 참여해서 정보를
공유하는 앱」을 한 줄씩 쪼개고, 줄마다 「지금 우리 앱에 무엇이 있나」와
「무엇을 정해야 움직이나」를 답니다. 결정이 끝날 때마다 **2번 결정 기록부**에 적습니다.

**이 문서 하나만 봅니다.** 계획을 두 곳에 두면 곧 서로 다른 말을 합니다(CLAUDE.md 5번).

- 원문: 2026-09-23 사장님 말씀 — 「시그널플래너처럼, 고객도 같이 참여하여 정보를 공유할 수 있는 어플」
- 지금 단계: **결정 전.** 아래 결정 C-01~C-09 중 **처음 셋(C-01·C-02·C-03)** 이 정해지면 1단계를 만들 수 있습니다
- 시그널플래너의 실제 기능 목록은 이 문서에서 **추측해 적지 않았습니다**(1번 규칙). 비교가 필요하면
  사장님이 쓰시는 화면을 캡처해 주시면 그걸 보고 3번 표에 붙입니다

---

## 0. 한 줄로

> 지금 APEX 는 **설계사 혼자 여는 화면**입니다. 고객은 설계사가 보여 줄 때만 봅니다.
> 이것을 **고객이 자기 폰에서 직접 열고, 직접 채워서 돌려보내는** 쪽으로 넓힙니다.

그런데 이 앱의 가장 단단한 규칙 하나가 정면으로 걸립니다 —

> **실명은 이 브라우저에만. 서버에는 마스킹만.** (CLAUDE.md 3번)

고객이 같이 쓰려면 고객 자료가 **어딘가에서 두 사람 사이를 오가야** 합니다. 그래서 이 계획의
뼈대는 기능이 아니라 **「자료가 어디에 머무는가」를 단계마다 한 칸씩만 늘리는 것**입니다.

```
1단계  서버에 아무것도 안 남는다    — 주소(# 뒤)에 담아 보낸다      ← 오늘 규칙 그대로
2단계  고객이 채워 돌려보낸다        — 역시 주소로, 또는 90일 뒤 사라지는 우편함
3단계  고객이 로그인해 자기 칸을 연다 — 고객 본인이 동의하고 적은 것만 서버에
4단계  알림 · 가족
```

**한 단계가 끝나 실제로 고객 몇 분께 써 보기 전에는 다음 단계로 안 넘어갑니다.**
3단계는 개인정보 동의·보관·삭제 절차가 붙는 일이라, 1·2단계로 「고객이 정말 여는가」를
먼저 확인하는 편이 쌉니다.

## 3. 단계 — 무엇을 만드나

### 1단계 · 고객 한 장 (서버에 남는 것 0)

**설계사가 「고객에게 보내기」를 누르면, 고객 폰에서 열리는 읽기 전용 한 장.**

- 새 화면 `app/me.html` (+ `app/me.webmanifest`) — 폰에서 앱처럼 열린다(C-01)
- 담는 것: 보장 요약(담보·금액) · 다음 상담 날짜 · 설계사 연락처 · 「지금 준비하실 것」 한두 줄
- 자료는 **주소 `#` 뒤에** 담는다. `#` 뒤는 서버로 가지 않는다 — 「한장 보험료 비교」 고객 링크와 같은 방식.
  길면 이미 있는 `shortlink.js`(누를 때만 저장 · 90일 만료)를 쓴다
- **이름은 담지 않는다.** 화면 머리에는 「고객님」 또는 고객이 **자기 폰에서 직접 적은 호칭**(그 폰 localStorage)
- 폰에 담아 두면 다음에 열 때도 그 한 장이 그대로 뜬다(그 폰에만 저장)

지켜야 할 것 (1단계에서 제일 잘 깨질 자리):

| 자리 | 규칙 | CLAUDE.md |
|---|---|---|
| 모르는 담보 | 빈칸은 「확인 안 됨」, **0원으로 적지 않는다** | 1 |
| 보험료·보장 | 「심사 결과에 따릅니다」 | 2 |
| 세금 이야기 | 결론 금지, 「요건 충족 시」 · 숫자 금지 | 2 |
| 금액 단위 | `xxxWon()` = 만원 · `xxxWonR()` = 원 · 큰 금액은 억 | 4 |
| 인쇄·PDF 저장 | `tnum` 은 `@media screen` 안에만 | 4-1 |
| 평균으로 채운 값 | 고객 화면에서도 「평균」이라고 밝힌다 | 1 |

### 2단계 · 고객이 채워 돌려보낸다

- 1단계 한 장에 **「상담 전에 적어 주세요」** 칸 — 팩트파인딩 질문지 **그 질문지 그대로**(두 벌 금지, `check-ffsame` 이 본다)
- 다 채우면 **답이 담긴 주소**를 만들어 카톡으로 설계사에게 회신 → 설계사가 APEX 에 붙여 넣으면 고객 카드에 들어간다(C-05)
- 고객이 가진 보험 PDF 를 **고객 폰 안에서** 읽어 담보·금액만 담는다(C-06). 읽기는 기존 PDF 규칙을 **그대로 가져다 쓴다** —
  `pdfTextTrust` 로 먼저 믿을 수 있는지 묻고, 못 믿으면 그림으로 다시, 모든 기다림에 시간 제한
  - ⚠ `app/index.html` 의 PDF 함수를 `me.html` 에 **복사해 넣으면 쌍둥이**가 됩니다(5번).
    먼저 작은 공용 파일(예: `app/apex-pdfread.js`)로 **떼어 내고 두 화면이 같이 부르게** 한 뒤 씁니다.
    이 떼어 내기는 보장분석(`baba*`) 세션과 겹치므로 그 세션과 순서를 맞춥니다

### 3단계 · 고객 칸 (로그인)

여기서 처음으로 **고객 자료가 서버에 머뭅니다.** 그래서 이 단계는 결정 C-02·C-03·C-09 가
끝나야 시작합니다.

- 고객은 **초대 코드**(설계사가 보낸 링크)로만 들어온다 — 아무나 가입하는 앱이 아니다
- 서버에 두는 것은 **고객 본인이 동의하고 적은 것 + 설계사가 「보내기」를 누른 것**뿐
- 설계사 쪽 고객 카드의 실명 규칙은 **그대로**(서버엔 마스킹). 고객 칸은 설계사 고객 카드와 **id 로만** 잇는다
- 고객이 「내 정보 지우기」를 누르면 그 자리에서 전부 지워진다(동의 철회)

표 모양(초안 — 만들 때 `migration_NN_client_portal.sql` 로, 주석은 `/* */` 만):

```sql
/* 고객 칸 — 고객 본인 계정과 설계사의 고객 카드를 잇는 줄 */
create table if not exists public.portal_members(
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id) on delete cascade,     /* 고객 본인 로그인 */
  advisor_id uuid not null references public.profiles(id) on delete cascade,
  client_id uuid references public.clients(id) on delete cascade,
  invite_code text unique,                                        /* 한 번 쓰면 비운다 */
  consent jsonb not null default '{}'::jsonb,                     /* 무엇에 언제 동의했나 */
  created_at timestamptz not null default now()
);

/* 설계사가 「고객에게 보내기」를 누른 것 — 고객은 읽기만 */
create table if not exists public.portal_shared(
  id uuid primary key default gen_random_uuid(),
  member_id uuid not null references public.portal_members(id) on delete cascade,
  kind text not null,             /* 'summary' | 'proposal' | 'appt' */
  content jsonb,
  created_at timestamptz not null default now()
);

/* 고객이 채워 보낸 것 — 설계사는 읽기만 */
create table if not exists public.portal_inbox(
  id uuid primary key default gen_random_uuid(),
  member_id uuid not null references public.portal_members(id) on delete cascade,
  kind text not null,             /* 'ff' | 'coverage' */
  content jsonb,
  created_at timestamptz not null default now()
);
```

RLS 원칙(이것이 이 단계의 전부입니다):

- 고객은 `portal_members.user_id = auth.uid()` 인 **자기 줄만** 읽는다. 다른 고객 줄은 존재 자체가 안 보인다
- 고객은 `portal_shared` 를 **읽기만**, `portal_inbox` 에는 **쓰기만**
- 설계사는 `advisor_id = auth.uid()` 인 줄만. **팀장·관리자 전체 조회(`is_admin()`)를 여기엔 붙이지 않는다** — 고객이 동의한 상대는 그 설계사 한 사람이다
- 고객 계정은 **설계사 역할이 아니다.** 고객이 `dbs`·`clients`·`saved_reports` 를 읽을 수 있는 정책이 **하나라도** 생기면 안 된다 — 기존 정책이 `to authenticated` 로 열려 있으면 고객 로그인도 authenticated 입니다. **이것이 3단계에서 가장 위험한 자리입니다.** 만들기 전에 기존 정책 전부를 훑어 `profiles` 에 있는 사람만 통과하게 좁혀야 합니다

### 4단계 · 알림 · 가족

- 고객 폰 알림은 기존 `push-core.js` 를 그대로 쓴다(두 벌 금지). 잠금 화면에 뜨므로 **이름·금액 없이**: 「담당 설계사가 새 자료를 보냈습니다」
- 알림은 **보낼 때 한 번**. 고객 화면이 주기적으로 서버를 묻지 않는다(7번). 열 때 한 번만 받는다
- 가족 공유는 C-03 이 「받는다」로 바뀐 뒤에만

## 4. 서버 값 — 무료 한도 (7번)

고객이 생기면 부르는 사람이 설계사 수에서 **고객 수**로 늘어납니다. 한도를 세 배 넘겨 로그인이 막힌 적이 있습니다.

- 1·2단계는 서버 호출이 **0** (짧은 주소를 누를 때만 한 번)
- 3단계부터: 고객 화면은 **열 때 한 번**, `document.hidden` 이면 쉰다, 목록에 본문을 미리 다 받지 않는다
- `check-egress.js` 가 `me.html` 도 보게 한다

## 5. 갈래 · 세션 가이드 (11번)

새 갈래를 하나 둡니다.

| 갈래 | 맡는 곳 | 이름 접두사 |
|---|---|---|
| 자. 고객앱 | `app/me.html` · `app/me.webmanifest` · (3단계) `migration_NN_client_portal.sql` | `cp*` · `CP_*` · `.cp-*` |

`app/index.html` 쪽에서 손대는 것은 **「고객에게 보내기」 단추 하나와 받아 붙이기 하나**뿐입니다 —
그 두 함수도 `cp` 접두사로 만들어 다른 세션과 이름이 안 겹치게 합니다.

### 점검을 먼저 쓴다 (8번)

`scripts/check-cportal.js` (이름이 없는지 먼저 확인) → `scripts/checks.tsv` **맨 끝에 한 줄**.
각 줄마다 **일부러 되돌려서 빨간불이 켜지는지** 봅니다.

| 무엇을 잡나 | 어떻게 |
|---|---|
| 고객에게 가는 주소·서버 값에 실명이 없나 | 「홍길동」 견본을 넣고 만든 주소·요청 본문에 그 글자가 없는지 |
| 모르는 담보가 0원으로 찍히지 않나 | 담보 하나를 `null` 로 두고 화면에 「0원」이 없는지 |
| 「심사 결과에 따릅니다」 · 「요건 충족 시」가 붙나 | 보험료·세금 문구가 뜨는 화면에서 |
| 되풀이 호출이 없나 | `me.html` 에 `setInterval` + fetch 가 없는지 |
| 인쇄에 `tnum` 이 없나 | `@media screen` 밖 `font-feature-settings` |
| (3단계) 고객 계정이 설계사 표를 못 읽나 | 견본 고객으로 로그인해 `dbs`·`clients`·`saved_reports` 가 0줄인지 |

### 세션에 이렇게 시킨다 (복사용)

> `app/me.html` · `app/me.webmanifest` 만 만드십시오. `app/index.html` 에는 `cp` 로 시작하는
> 함수만 새로 두고, 다른 이름은 건드리지 마십시오. `APP_BUILD` 두 줄은 건드리지 마십시오.
> 먼저 `docs/고객참여앱_계획.md` 의 1단계와 「지켜야 할 것」 표를 읽으십시오.
> 새 점검은 `scripts/check-cportal.js` 로 만들고 `scripts/checks.tsv` **맨 끝에** 한 줄을 붙이십시오.
> 시작 전에 `git fetch origin main && git checkout -B <브랜치> origin/main`, 밀기 전에
> `node scripts/lane.js`, 끝나면 바로 미십시오.
