# 전자책 「무기는 쓸 수 있어야 한다」 — 만드는 법

아티팩트: https://claude.ai/code/artifact/8f25654d-e304-44b9-98c4-5910251df678

이 폴더는 **전자책을 고칠 때 쓰는 도구**만 들어 있습니다.
완성본(`book-final.html`, 5.6MB)은 폰트와 그림이 박혀 있어 저장소에 넣지 않습니다 —
아티팩트에서 받아 오면 됩니다.

## 🚫 앱 코드에 손대지 않습니다

전자책 작업은 **읽기만** 합니다. `app/**` · `db-crm*.html` · `scripts/**` ·
`migration_*.sql` 은 고치지 않습니다. 이유는 `docs/전자책_인계.md` 0장에 있습니다.

## 앞선 세션에서 밟은 함정 — 반복하지 말 것

- **CSS 클래스 충돌.** 새 클래스는 반드시 기존 161개와 겹치는지 먼저 봅니다.
  지금까지 쓴 접두사: `rdr-` `nmb-` `cyc-` `pw` `pin` `mp-` `op-` `st-` `dt-` `qt-`
  `brain` `bn-` `fl-` `sx-`.

- **표로 만들면 잘립니다.** 좁은 화면에서 표는 가로로 잘리거나 스크롤이 생깁니다.
  「한눈에 다 보여야 하는」 내용은 **표 대신 SVG 카드**로 그리세요 —
  `frag_six.py` 가 그 본보기입니다. 줄바꿈을 직접 정하니 어디서도 안 잘립니다.
  칩(태그)은 `tw()` 로 글자 너비를 어림해 자동 줄바꿈합니다.

- **본문 폭을 넘기는 그림.** 큰 지도 둘(`.brain`)은 740px 본문 폭으로는 글씨가 너무 작아져서
  `width:min(96vw,1080px); margin-left:50%; transform:translateX(-50%)` 로 화면 폭까지 넓혔습니다.
  `100vw` 를 쓰면 스크롤바 때문에 가로가 넘치니 **96vw 를 유지**하세요.
  인쇄에서는 `@media print` 가 원래 폭으로 되돌립니다.
- **장 번호.** 장을 끼워 넣으면 앵커(`#sN`) · `제 N 부` 딱지 · 차례 ·
  표지 읽는 순서 · 꼬리말 · 본문 상호참조가 **전부** 따라 바뀝니다.
  `build3.py` 가 그 전부를 한 번에 처리하니 그 틀을 쓰십시오.
- **주석과 id 가 어긋나 있습니다.** `<!-- ═══ 5부 ═══ -->` 가 `id="s6"` 앞에
  붙어 있는 식입니다. 삽입 자리를 잡을 때 주석 번호를 믿지 마십시오.
- **큰 숫자.** 화면 수(85) · 그림 수(114) · 갈래 수(14)는 표지 · 차례 ·
  이동 막대 · 서장 · 도구 백과 머리말에 흩어져 있습니다.
- **말투.** 「…십시오」는 쓰지 않습니다. 본문은 「…습니다」, 시키는 말은
  **「…세요」와 「…시죠」를 섞어** 권유하듯 씁니다(`build6.py` 가 하나 걸러 하나씩 바꿉니다).
  다만 **고객에게 묻는 말은 「…세요?」가 맞습니다** — 「어떤 부분이 걸리세요?」를
  「걸리시죠?」로 바꾸면 뜻이 달라집니다. 따옴표 안 물음문은 손대지 마세요.

- **날짜는 건드리지 않습니다.** 「입사 몇 개월 차」(업력)는 참고로 낮춰도 되지만,
  **고객 날짜**(배정일·마지막 통화일·상담 약속·마지막 터치)는 이 일의 심장입니다.
  2부의 날짜 절과 7/90/365 리듬이 그 자리입니다 — 약하게 쓰지 마세요.

## ✅ 화면에 없는 말은 책에도 없습니다 — 가장 중요한 규칙

**화면에 찍힌 글자가 옳습니다.** 책이 다르게 부르고 있으면 **책을 고칩니다.**
앱은 절대 고치지 않습니다. 설명서의 말이 화면과 다르면 그 순간 설명서가 아니게 됩니다.

`ui.py` 가 `app/index.html` · `db-crm.html` 에서 화면 글자를 뽑아 `ui.json` 에 담고,
`audit.py` 가 책의 `<span class="chip">` (화면 이름을 자처하는 자리)과 `「」` 인용을
그 목록과 맞춰 봅니다. **글을 새로 쓴 뒤에는 반드시 한 번 돌리세요.**

## 🧾 낱장 문서(사업계획서 · 처방전)를 뽑을 때

`plan_gen.py` · `rx_gen.py` 는 **A4 세로 낱장**을 만들고 `*_shot.js` 가
PNG(2480×3508)와 PDF 로 뽑습니다.

- **한글 폰트.** 이 환경에는 쓸 만한 한글 폰트가 없습니다(WenQuanYi·Unifont 뿐).
  책에 박힌 **Pretendard 다섯 벌을 떼어 `fonts.css`** 로 두고 낱장에서 재사용합니다.
  `book-final.html` 에서 `@font-face` 를 긁어 오면 됩니다.
- **맺음 상자가 늘어납니다.** `.pg` 가 flex column 이고 `.ft{margin-top:auto}` 라,
  마지막 상자에 `flex:none` 을 안 주면 **남은 공간을 다 먹어** 거대한 빈 상자가 됩니다.
- **쪽이 비면 채우세요.** 한 쪽이 30% 넘게 비면 인쇄물로 못 씁니다.
  내용을 옮기기보다 **빠진 절(문제 진술 · 일정 · 위험)을 넣는 편**이 낫습니다.
- **말투는 지어내지 마세요.** `rx_gen.py` 5쪽(말투 카드)의 예문은
  **앱 주석에서 그대로 뽑은 것**입니다. 새 문장을 쓸 때도 같은 방법을 쓰세요 —
  `app/index.html` 의 `/* … */` 주석을 긁으면 대표님이 쓴 문장이 1,900개 나옵니다.
  쓰는 꼴 여섯: **A가 아니라 B · 아무도 안 — · 하나만 · 이랬다→그래서 ·
  하지 않는다 · 숫자로 못박기.**
- **처방의 화면 이름은 반드시 대조.** `rx_data.py` 를 고치면
  TABS 의 `title` 과 맞는지 확인하세요 — 없는 화면을 처방하면 설명서가 거짓말이 됩니다.

## 📅 앱이 자라면 책의 숫자가 먼저 틀립니다

앱은 계속 바뀝니다. **화면 수와 갈래별 개수는 책 곳곳에 흩어져 있어서**
한 군데만 고치면 반드시 어긋납니다. `build14.py` 가 그 전부를 한 번에 처리합니다.

숫자가 박혀 있는 자리 — **표지 통계 · 표지 「이 책에 들어 있는 것」 · 이동 막대 ·
차례 · 12부 제목 · 갈래 지도 SVG · 갈래 카드 · 도구 백과 접이칸 머리 ·
윤시현의 뇌 지도 · 4부 머리말 · 출처 표기.**

**세는 법** — `열네 갈래 안의 화면` + `받쳐 주는 다섯`. 2026-08-19 기준 **83 + 5 = 88**
(`실행 체크판`이 조직 관리와 업무매뉴얼 도구 양쪽에 있어 고유 이름은 87).
`ui.py` 를 돌리면 갈래별 개수가 나옵니다 — **그 숫자를 그대로** 쓰세요.

**지도 SVG 의 화면 수**는 왼쪽 칸이 `text-anchor="end"`, 오른쪽 칸이 `start` 라
정규식을 앵커에 묶으면 오른쪽 일곱 칸을 놓칩니다. `[^>]*` 로 두세요.

2026-08-19 판에서 늘어난 것 — 상담 도구 9→10(**미끼상품&접촉전략**),
계약·청구 6→7(**자동차사고 과실·보상**), 콘텐츠 제작 7→8(**고객에게 전할 뉴스**).
**「미끼 레이더」는 보험전략실(`role:'hq'`, 사업단장 전용)로 남아 있고,
설계사가 쓰는 것은 「미끼상품&접촉전략」입니다 — 둘은 다른 화면입니다.**

## 🔢 앱의 계산은 앱에서 그대로 옮깁니다

18부(레벨업)는 **성장판의 점수 공식을 책에 그대로** 옮겼습니다.
숫자를 지어내면 독자가 화면과 대조하는 순간 신뢰를 잃습니다.

- 여섯 축의 **목표·단위·설명·고치는 법**은 앱의 `GB_AX` 를 그대로 옮긴 것입니다.
- 점수 = `Math.max(0, Math.min(100, Math.round(실적/목표*100)))`,
  총점 = 여섯 축 평균 (`gbScore`).
- 「한 축을 기준까지 올리면 +N점」의 N 은 `Math.round(벌어진 만큼 / 6)` 입니다.
- 열두 주제는 `GB_CUR`, 리더의 한 주는 `GB_WEEK`,
  「놓치고 있는 사람」 일곱 조건은 `gbMiss` 에서 왔습니다.

**반올림을 파이썬 `round` 로 하지 마세요.** 파이썬은 `round(12.5)==12`
(짝수로 붙임)인데 자바스크립트는 `13` 입니다. `frag_level.py` 의
`jsr()` 처럼 `floor(x+0.5)` 를 쓰셔야 화면과 같은 숫자가 나옵니다.

「가독성이 너무 떨어진다」는 지적을 받았습니다. 그래서 정한 것들입니다.

- **크게 먼저, 세부는 뒤로.** 맨 앞은 `s-road`(로드맵 — 네 고비) →
  `s-who`(설계사 하루 · 매니저 하루) 순입니다. 상세는 전부 그 뒤입니다.
- **한눈에 보여야 하는 것을 SVG 로 만들지 마세요.** `frag_two.py` 가 그렇게
  했다가 **글자가 고정 크기라 좁은 화면에서 작아져** 읽을 수 없었습니다.
  `frag_use.py` 처럼 **HTML + CSS 격자**로 쓰면 흐르니까 안 잘리고,
  글자 크기는 읽는 사람 설정을 따릅니다.
  SVG 는 **그림일 때만** 씁니다(마인드맵·파이프라인).
- **본문 15.5~17px · 줄간 1.7 이상.** 카드 안 여백은 20px 아래로 내리지 않습니다.

## 🔷 로고는 앱에 있는 것을 그대로 씁니다

표지 로고는 **앱 사이드바(`.sb-logo`)** 에 있는 것이 원본입니다. 새로 그리지 마세요.

- **마크** — 획 두 개짜리 A. `viewBox="0 0 240 220"` 의 `path` 둘을 그대로 옮깁니다.
- **워드마크** — `APEX`(흰색) + `YUN PRO`(**`#60A5FA`**). 붙여 쓰지 않고 한 칸 띄웁니다.
- 표지가 어두우므로 마크는 `fill:currentColor` + `color:#fff` 로 둡니다.

`b,strong{color:var(--g900)}` 이 전역에 걸려 있어 **`.lg-w b{color:#fff}` 를 반드시
따로 줘야** 「APEX」가 어둡게 죽지 않습니다. 한 번 여기서 당했습니다.

앞 판은 은색 그라디언트에 다른 모양 A 를 쓰고 있었습니다 — 앱과 다른 로고였습니다.

「몇 개월 차」가 아니라 「이 고객이 어느 단계인가」가 기준입니다.
