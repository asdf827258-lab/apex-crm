# APEX YUN PRO 플랫폼 — 전체 도구 명세서 (SPEC)

> 출처: 커넥션랩스(CONNECTIONLABS) 대시보드 스크린샷 역설계 분석.
> 목적: 동일한 **기능 카테고리**를 APEX YUN PRO 브랜드로 **독자 구현**하기 위한 명세.
> ⚠️ 커넥션랩스의 코드·문구·데이터를 복제하지 않는다. 같은 "종류"의 도구를 새로 만든다.

## 0. 화면 분석 요약

스크린샷에서 확인된 구조:

- **상단 배너 영역(광고/모집)**: YouTube 보험학개론 / 단체 카톡방 / 지사·직영 모집 / 퍼미션DB / 배너광고 모집 → *도구가 아님*. 우리 버전에서는 "공지/배너" 영역으로 **설정 가능한 카드**로 대체(선택).
- **좌측 사이드바(안내)**: 이용방법·가이드, 사이트 소개, API 키 발급.
- **좌측 사이드바(카테고리 바로가기)**: 대시보드, 네이버 블로그, Threads, 인스타그램, 유튜브&릴스, 외부글 심의필터, 콘텐츠 캘린더, 히스토리, AI 보장분석 …
- **메인(전체 도구)**: 8개 카테고리 × 다수 도구. 화면 하단에 **추가 카테고리 6개가 잘려 있음**(스크롤 시 더 존재). → 추가분은 발견 즉시 본 문서에 추가.

확인된 도구: **35개 / 8 카테고리**.

## 1. 구현 유형 분류 (가장 중요)

각 도구는 셋 중 하나다. 이 분류가 빌드 우선순위를 정한다.

| 유형 | 의미 | 키 필요 | 빌드 난이도 |
|---|---|---|---|
| **CALC** | 순수 클라이언트 계산/조회 (브라우저 안에서 완결) | ❌ 불필요 | 낮음 — 즉시 가능 |
| **AI** | Claude API 호출로 생성·분석 | ✅ 사용자 키 | 중간 — 프롬프트 설계 |
| **EXT** | 외부 시스템/데이터/자동화 필요 (백엔드·외부 API·정부사이트) | 경우에 따라 | 높음 — 또는 링크아웃 |

**원칙:** CALC부터 전부 완성 → AI 도구 → EXT는 "링크아웃 + 안내" 또는 별도 백엔드 과제로 분리.

## 4. 빌드 우선순위 (권장)

1. **계산기 4종(CALC)** — 키 없이 즉시 가치. (본 빌드 완료)
2. **레퍼런스 링크아웃(EXT-link)** — 보험사 전산/HIRA/내보험찾아줌/디지털 명함/키워드 조합기. 빠르고 안전.
3. **AI 도구 신규분** — 외부글 심의필터·금소법 AI(규칙 공유), AI 보장분석, 비포&애프터, 제안서 비교/카톡설명, AI 상담 피드백, 니즈 시뮬레이터, 메타 광고 가이드, 리드 랜딩페이지, 소상공인 답글, 알릴의무/건강검진/실비.
4. **데이터셋 의존(CALC+data)** — 질병코드·특약, 수술명 검색 (KCD/수술 데이터 확보 후).
5. **백엔드 과제(EXT)** — 키워드 검색량, 스레드 반자동발행, 네이버 광고 대량등록기. 별도 서버 설계.

## 5. 준법·안전 가이드 (모든 AI 도구 공통)

- 보험광고는 **보험업법·금융소비자보호법** 적용. 수익/환급 단정 보장, 타사 비방, 불안 조장 금지.
- 생성물은 **게시·사용 전 소속사 준법감시(광고 심의)** 확인 권장 문구를 항상 노출.
- 건강/의료 도구는 **진단이 아님**, 인수/고지 도구는 **최종 판단은 보험사**임을 명시.
- 후기 콘텐츠는 **실제 후기 기반**일 때만. 허위 후기 생성 금지.
- 개인정보(주민번호·연락처 등)는 결과물·URL에 넣지 않음.

## v3 구현 현황 (전 메뉴 · Claude 엔진)

엔진은 전부 **사용자 Claude**(설정의 내 키 또는 서버 프록시). Gemini 미사용.

### 콘텐츠 제작
- 블로그 / Threads / 인스타그램 / 유튜브&릴스 — 공통 리치 폼(보험종류·라이프스테이지·연령·성별·지역GEO·톤·고민·CTA·추가프롬프트 + **금소법 필터링 ON/OFF**) [AI]
- 외부글 심의필터(simui) [AI] · 콘텐츠 캘린더(calendar) [AI]

### 제안서·보장분석 (PDF 업로드 → Claude)
- AI 1:1 보장분석(bojang): 리포트 PDF + 설계사 집중 컨설팅 포인트 21칩(5그룹) + 직접 코멘트
- **비포 & 애프터(baba): 2모드 — ① 전체 담보 비교 / ② 시니어 간소화(핵심담보·치료비·가격)**, 기존 보장(필수) + 신규 슬롯 1~5
- 제안서 비교(compare): 설계안 1~3, 슬롯당 합산설계 지원
- 제안서 카톡설명(katalk): 최대 5 PDF + 나만의 어조 샘플

### 보험 레퍼런스
- 예외질환 인수확인 / 질병코드·특약 / 수술명 검색 [AI, 약관·보험사 기준 명시]
- 보험사 전산 / 건강보험심사평가원 / 숨은보험금찾기 [공식 링크보드]

### 마케팅
- 메타 광고 가이드 / 리드 랜딩페이지 [AI] · 키워드 조합기 / 디지털 명함 [CALC] · 키워드 검색량 [링크]

### 고객 상담 도구
- AI 상담 어시스턴트(상담스크립트·반론·보장화법·TA·리드응대) / AI 상담 피드백 / 니즈 시뮬레이터 / 금소법 AI [AI]

### 건강·의료 분석

### 외부 프로그램
- 소상공인 AI 답글 [AI] · 스레드 반자동발행 / 네이버 광고 대량등록기 [링크, 백엔드 필요]

## v3.1 리포트급 출력 + 사용가이드

### 리포트급 렌더링
- renderMd 강화: Markdown 표(| |) → 스타일 표, blockquote(>) → 콜아웃(c-warn/c-ok/c-key/c-tip 자동 분류), --- → 구분선
- renderReport(title,subtitle,md): 브랜드 표지(rpt-cover) + 본문 + 면책 푸터
- reportResultBox: 인쇄(printReport, @media print + #printRoot), HTML 저장(downloadReport, 인라인 CSS), 원문 복사
- bojang/baba(full)/compare → report:true 로 리포트 셸 출력. katalk은 메시지형(plain).

## v3.2 자동 연결(APEX_CONFIG)
- 파일 상단 `var APEX_CONFIG={apiKey,proxyUrl,model}` 한 곳만 채우면 자동 연결.
- applyEmbeddedConfig() 가 init에서 1회 적용: proxyUrl(우선) → conn=proxy, apiKey(sk-) → conn=direct, model 오버라이드. window.__APEX_LOCKED 플래그.
- getModel()은 APEX_CONFIG.model 우선. isAutoConnected()로 설정 화면에 '자동 연결됨' 배너 표시(direct면 파일 공유 금지 경고).
- 보안: 키 하드코딩(apiKey)은 '내 기기 전용'이며 배포 금지. 배포·상업화는 proxyUrl(서버 env 키) 사용.
