# 이어받기 — 다른 세션에서 계속할 때

이 문서만 읽으면 어디까지 됐고 다음에 무엇을 하면 되는지 알 수 있습니다.
작업은 항상 `git fetch origin main` → 최신 main 에서 브랜치를 따고 시작합니다.

## 이 앱이 굴러가는 규칙

- 화면 하나 = `var TABS` 에 항목 추가 → `go(tab)` 분기 → `renderXxx()` 가 HTML 문자열을 돌려줍니다.
  그린 뒤 할 일은 `osXxxAfterRender()` 에 넣습니다. **기존 경로는 건드리지 않고 더하기만** 합니다.
- 서버는 `osClient()` (이미 연결된 Supabase), 내 정보는 `OS.profile` 을 씁니다.
- AI 는 `callAI(system, user, maxTokens, genId)` 를 그대로 씁니다.
- ES5 로 씁니다 — `var` · `function` · 템플릿 리터럴 없이.
- 보험 관련 문구에는 금융소비자보호법에 따른 안내를 함께 넣습니다.
- 고친 뒤에는 **반드시** 문법 검사와 화면 점검을 돌립니다.

```bash
node scripts/check-html.js app/index.html
python3 scripts/check-sql.py
NODE_PATH=/opt/node22/lib/node_modules node scripts/smoke.js
```

## 새 표를 만들지 않는 저장 방식

새 기능은 이미 있는 표에 얹습니다. **`SETUP_VER` 는 32 그대로** — SQL 을 다시 돌릴 일이 없습니다.

| 기능 | 저장 자리 |
|---|---|
| 실행 체크판 | `daily_checks(member_id, check_date, scope, items)` |
| 도와줄 것 · 합격 | 같은 표, `scope='help'` / `'pass'`, `check_date='2000-01-01'` |
| 고객 365일 | `saved_reports(kind='client_meta')` — 고객 한 명에 한 줄 |
| 재무설계 상담자료 | `saved_reports(kind='fp_deck')` |
| **AI 보고** | `saved_reports(kind='ai_report')` — `content.mid` 가 누구 보고인지 |

`saved_reports` 의 RLS 는 `advisor_id = auth.uid() or is_admin()` 입니다.
그래서 **저장은 언제나 내 이름으로** 남습니다. 리더가 팀원 보고를 만들면 그 줄의 주인은 리더입니다.
`kind='ai_report'` 줄은 성장판 「자료」 축 집계에서 `.neq('kind','ai_report')` 로 빼 두었습니다 —
빼지 않으면 보고를 만들 때마다 점수가 올라갑니다.

## AI 관리판이 어떻게 생겼나

왼쪽 카테고리 아홉 개 → 오른쪽에 그 칸만. `AR_CAT` 이 목록이고 `arBodyHtml(cat)` 이 분기입니다.

| 칸 | 그리는 함수 | 무엇을 보나 |
|---|---|---|
| 피드백 | `arMeHtml` | AI 보고 다섯 칸 |
| 스케줄 관리 | `arSchedHtml` | 잡힌 약속 · 고객 할 일 날짜순 · 이번 주 체크판 |
| 본인 역량 체크 | `arSkillHtml` | `GB_CUR` 열두 개, 누르면 `gbStamp` |
| 해야 할 일 | `arTodoHtml` | `arTodoList()` — 밀린 것부터 |
| 본인 점수판 | `arScoreHtml` | 여섯 축 + 팀 평균 + `gbGapList` 처방 |
| 부재·거절 재관리 | `arColdHtml` | `arCold(who,일수)` — 1주·2주·한 달 |
| 기고객 재관리 | `arOldHtml` | `arOld(who)` — 90일+ 또는 다음 할 일 없음 |
| 리더 할 일 | `arLeadHtml` | `CK_LDR` — 누구나 열람, `arIsLead()` 면 체크 |
| 팀원 관리 | `arTeamHtml` | 팀원 전원 + 각자 보고 |

- 배정 DB 한 건 한 건은 `AR.db` (`arDbCalc`), 고객 한 사람 한 사람은 `AR.cliRows` (`arCliRows`).
- 통화는 30일이 아니라 **최근 4000건**을 읽습니다. 마지막 통화가 40일 전이어도 알아야 다시 겁니다.
- 아침 비서는 `arBriefMaybe()` — `osOnLogin` 에서 하루 한 번. 끄기는 `apex_ar_brief_off`.
- **오전 8시 자동 보고**는 `arAutoArm()` → 10분마다 `arAutoRun()`. `AR_H=8` 이 기준 시각.
  리더면 팀원 전원(`arNeedToday`), 팀원이면 자기 것 하나. 하루 한 번(`apex_ar_team_<날짜>`).
  끄기는 `apex_ar_auto_off`. **브라우저 안에서만 도는 앱이라 아무도 안 켜면 서버가 대신 눌러
  주지 못합니다** — 다만 지점장이 열면 팀원 전원 것을 대신 만들어 둡니다.
- 전화 습관은 `arCrmDeep(who)` / `arCrmDeepText(who)`. `AR.calls` 에 담아 둔 통화 기록에서
  결과 분포 · 시간대 · 요일 · 재시도 간격 · 주간 추이를 계산합니다.
  **고객 이름·전화·메모는 담지 않습니다** — 숫자와 패턴만 AI 로 넘어갑니다.
- 주기 알림은 `arNudgeStart()` — 95분마다, 하루 세 번까지.
- 「무슨 말로 다시 걸까」는 `arTalk(kind)` — **건수만** AI 로 넘깁니다. 고객 이름은 넘기지 않습니다.

## TEAM 총괄 관리 · 설정이 어떻게 생겼나

**TEAM 총괄 관리** — 실행 체크판 · 성장판 · 내 코칭 · 본인 점검란을 한 칸에 모았습니다.
`TH_CAT` 이 목록, `thBody(cat)` 이 분기입니다. **화면을 두 벌로 만들지 않았습니다** —
원래 화면이 쓰던 그리기 함수를 그대로 부르고, 원래 쓰던 칸 이름(`#ckPane` `#gbPane`
`#mcPane` `#acadBody`)을 그대로 둡니다. 그래서 `ckPaint()` `gbPaint()` 같은 기존 코드가
그대로 돕니다.

- 체크판을 허브 안에서 열 때는 `CK.hub=true` 로 위 탭 줄을 접습니다 (왼쪽이 그 일을 합니다).
- 옛 메뉴 네 개는 **지우지 않았습니다.** `hide:true` 를 붙여 사이드바에만 안 그립니다.
  `osTabAllowed()` · 요금제 판정 · 음성 명령(`go('ckboard')`)이 이 목록을 보고 돌기 때문입니다.
  `renderNav()` 이 `g.hide` 를 건너뜁니다.
- 성장판 칸은 `osTabAllowed('growboard')` 로 요금제를 다시 확인합니다.

**설정** — `SET_SEC` 여섯 칸(팀·권한 / 사업자·법무 / AI 연결 / 결제·구독 / 데이터·백업 /
점검·진단). 카드 사이사이에 `'</div><div class="set-sec" data-sec="…">'` 을 끼워 넣어
나눴습니다. 고른 칸은 `apex_set_sec` 에 남습니다.
카드 접기는 원래 있던 `osFoldApply()` 를 그대로 씁니다 — 처음 오는 사람에게는 칸마다
맨 위 한 장만 펼쳐 두고 나머지는 접습니다(그 기본값을 `apex_fold` 에 적어 둡니다).

## 정책·상품 뉴스가 왜 안 바뀌었나

**앞선 기록이 틀렸습니다.** 여기에 「Routine 이 어디에도 없었다」고 적어 두었는데,
확인해 보니 **2026-07-24 에 만들어진 Routine 이 이미 있었습니다**
(`trig_01L2bjNBZqPrNgfVkwJrbMy3` · 매월 1일 00:00 UTC).
그 Routine 은 **2026-08-01 에 실제로 실행됐습니다.** 그런데 PR 이 하나도 열리지
않았고 `asOf` 도 `2026-07` 그대로였습니다. 실행은 됐는데 결과물이 없었던 겁니다.

처음에는 지시문 탓인 줄 알고 고쳤습니다 — 「마커를 못 찾으면 변경 없이 종료한다」는
구멍을 없애고, 바꿀 게 없어도 PR 을 열도록 바꿨습니다. 그리고 8월 9일에 손으로 한 번
더 돌렸습니다. **그런데 또 빈손이었습니다** — 12분 돌고, 브랜치조차 안 올라왔습니다.

**진짜 원인은 지시문이 아니라 네트워크였습니다.** 이 환경의 나가는 길(egress proxy)이
정부·공공기관 도메인을 전부 막고 있습니다. 직접 확인한 결과입니다:

```
mofe.go.kr  www.fsc.go.kr  www.moef.go.kr
www.nts.go.kr  www.bizinfo.go.kr  nsp.nanet.go.kr   → 전부 403 (CONNECT 거부)
```

Routine 은 「1차 출처에서 확인되지 않으면 바꾸지 않는다」는 원칙을 지키도록 되어 있고,
그 1차 출처가 하나도 안 열리니 아무것도 못 바꾸고 끝난 것입니다. 원칙은 맞았고
환경이 막았던 겁니다.

- **막힌 길 대신 검색으로 갑니다.** WebSearch 는 정상 동작하고 본문 요약과 실제 URL 을
  돌려줍니다. Routine 을 검색 중심으로 다시 짜고, **매월 1일 → 매주 월요일 아침 7시**로
  바꿨습니다 (`0 22 * * 0` UTC). 한 달에 한 번은 8월 3일 세제개편안 같은 것을 4주나
  늦게 알게 됩니다.
- **숫자는 둘의 규칙으로 지킵니다** — 서로 다른 출처 두 곳 이상이 같은 값을 말할 때만
  바꿉니다. 한 곳만 말하면 바꾸지 않고 「확인 필요」로 남깁니다.
- **사장님이 하시면 더 좋은 것** — claude.ai/code 에서 이 환경의 Network access 를
  `Full` 로 바꾸시거나 Custom 에 `*.go.kr` 을 넣으면 1차 출처까지 직접 읽습니다.
- 2026년 8월분은 그 방식으로 손으로 채웠습니다.
- 제가 중복으로 만들었던 Routine 은 지웠습니다. 매달 PR 이 두 개 열릴 뻔했습니다.
- 자동 병합하지 않습니다 — 숫자는 사람이 확인하고 병합합니다.
  끄려면 claude.ai 의 Routines 에서 「APEX 제도값·정책상품 뉴스 월간 자동 점검」을 끕니다.
- 앱에서도 바로 올릴 수 있게 했습니다 — 대표 계정에 「＋ 새 소식 올리기」.
  `app_config` 의 `biz_news_extra`(JSON 배열) · `biz_news_asof` 두 칸에 남고
  모든 팀원 화면에 즉시 보입니다. 새 표를 만들지 않았습니다.
- 표가 몇 달 지났는지 화면 맨 위에 적습니다. 3개월이 넘으면 붉게 경고합니다.

## 카드뉴스 캐러셀 — 모양 세 가지

`CN.style` 하나로 갈라집니다. `cnDrawSlide(sl,idx,n)` 이 맨 위에서 분기하고,
어느 모양이든 1080×1350 캔버스는 똑같습니다. 미리보기 HTML 도 모양마다 따로 있습니다.

| 값 | 단추 | 그리는 함수 | 어떻게 생겼나 |
|---|---|---|---|
| `news` | 📰 뉴스 카드 | `cnDrawSlide` 원래 갈래 | 색 배경 위에 글. 사진은 곁들임 |
| `full` | 🖼 사진 전체 | `cnDrawFull` | 사진을 꽉 채우고 검은 그라데이션 4단을 덮은 뒤 글 |
| `frost` | 🌫 흐린 칸 | `cnDrawFrost` | 사진은 그대로 두고 **아래 글자 자리만** 유리처럼 흐리게 |

`frost` 가 하는 일 — 사진을 6% 위로 올려 깔고, 아래쪽 62% 를 잘라내
`ctx.filter='blur(26px)'` 로 **그 부분만 다시 그린** 다음 남색 그라데이션을 얹습니다.
번호와 꼬리표는 사진 위에 어두운 알약으로, 본문은 흐린 칸 위에 놓습니다.
`full` 은 사진 전체가 어두워지는데 `frost` 는 사진 색이 살아 있습니다.

## 윤시스쿨 — 왜 도움이 안 됐고, 무엇을 고쳤나

**앞선 기록이 두 번 틀렸습니다.** 처음에는 「바깥 페이지라 못 고친다」고 적었는데,
`YOONSI_URL` 은 `윤시스쿨/index.html` — **이 저장소 안의 파일**입니다
(`app/윤시스쿨/index.html`). 같은 출처 iframe 이라 `window.parent` 로 앱에
그대로 닿습니다. 고칠 수 있었고, 고쳤습니다.

**진짜 문제는 이 화면이 앱과 아무 상관 없는 딴 세상이었다는 것입니다.**
오피스에는 지어낸 이름 서른둘(김상중·카리나·제니…)이 걸어 다니며 「연동 대기 💤」
라고 말했고, 진행판은 손으로 고객을 적어야 해서 늘 0 이었고, 할일은 그 지어낸
이름들에게 배정됐습니다. 전부 `localStorage` 에만 남았습니다.

지금은 부모 앱이 이미 읽어 둔 실제 기록을 그대로 봅니다 (`YS` 다리, `ysPull()`).

| 칸 | 전 | 후 |
|---|---|---|
| 🏢 오피스 | 지어낸 32명 | **실제 팀** — 구역 하나가 팀 하나, 말풍선이 그 사람의 지금 상태 |
| 📊 진행판 | 손으로 적는 고객, 늘 0 | **우리 DB** — 미진행·부재·거절·진행중·기고객·생일, 누르면 그 화면으로 |
| 📋 업무현황 | 지어낸 이름에게 배정 | **실제 팀원**에게 배정 + 「오늘 팀이 해야 할 것」 |
| 🤖 AI 비서 | 우리 숫자를 모름 | 물으면 **우리 팀 숫자**로 답함 (`ysCtx()`) |

- 읽어 오는 곳은 `parent.GB.rows`(성장판) · `parent.arTkCount()`(터치할 사람) ·
  `parent.gbTeamName()`(팀 이름). **새로 읽지 않습니다** — 앱이 읽은 것을 봅니다.
- `GB.rows[].days` 는 **체크판을 채운 날수**이지 멈춘 일수가 아닙니다.
  멈춘 일수는 `r.last`(마지막 활동일)에서 계산합니다 — `ysSince()`.
- 앱 밖(새 탭)에서 열면 예전 데모가 뜨고 **노란 띠로 데모라고 밝힙니다.**
  지어낸 이름을 진짜인 척 보여 주는 것이 원래 문제였습니다.
- 붙은 검사: `scripts/check-yoonsi.js` (30개). 지어낸 이름이 하나라도 섞이면 실패합니다.

「매일 모아 주는 것」은 그 옆에 따로 있습니다 — `daily` 탭.

|---|---|
| 상태 | `var DG=` · `renderDaily()` · `osDailyAfterRender()` |

| 이어짐 | 「내가 정한 것」(`memo`)과 지난번 방향이 **다음 날 프롬프트에 들어갑니다** |

## 어느 판을 보고 있나 — 「안 되어 있다」가 반복된 진짜 이유

하루에 세 번 「안 되어 있다」는 말이 나왔는데 **세 번 다 옛 판을 보고 계셨습니다.**
사람이 그걸 알 방법이 없었던 것이 문제였습니다.

- 사이드바 맨 아래에 **판 날짜**를 늘 적습니다 (`APP_BUILD`). 눌러서 복사됩니다.
- **PR 을 올릴 때마다 `APP_BUILD` 와 `APP_BUILD_NOTE` 두 줄을 함께 고칩니다.**
- 「안 바뀌었다」는 말이 나오면 **판 날짜부터 물어봅니다.** 화면을 뜯어보기 전에.

## 리더가 한 사람을 챙기는 자리 — 팀원 관리 하나

네 군데에 흩어져 있던 것을 한 칸에 모았습니다. AI 관리판 → 팀원 관리 → 이름 클릭.

| 순서 | 그리는 함수 | 어디서 계산하나 |
|---|---|---|
| 여섯 축 · 종합 점수 | `arNumsHtml` | 성장판 `GB.rows` |
| 📊 팀 평균과 견주면 | `arVsTeamHtml` | 성장판 `gbAvg` — **본인은 평균에서 뺍니다** |

| ☎️ DB 통합 CRM | `arCrmMiniHtml` | `arCrmDeep` |
| ☎️ 오늘 터치할 사람 | `arTkRow` | `arTouch` |

- **계산을 두 벌로 만들지 않았습니다.** 팀 평균은 성장판 것, 코칭은 팀 코칭 것을
  그대로 부릅니다. 두 화면이 다른 말을 하면 안 됩니다.
- 평균에서 본인을 빼는 이유 — 두 사람 팀이면 차이가 **정확히 절반**으로 희석돼
  처진 축이 안 보입니다. 몇 명 평균인지 화면에 적습니다.
- 팀 코칭 화면(`branch_coach`)은 그대로 둡니다 — **메모를 남기는 곳**입니다.

## DB 종류(카테고리) — 누구나 만들고 지운다

`dbs.source` 칸은 처음부터 있었습니다. 그런데 값이 네 개로 묶여 있었고
(`check (source in ('소개','지인','개척','일반'))`), 실제로 쓰는 방송·보장분석·농협
같은 이름을 넣을 수 없어서 **화면에서 종류 칸이 통째로 빠져 있었습니다.**

- 실행해야 하는 SQL 둘
  - `migration_36_db_source.sql` — 제약을 풀고, 칸이 없으면 만들고, 첫 목록을 심습니다
  - `migration_37_db_source_open.sql` — **팀원도 목록을 고칠 수 있게** 엽니다
- 종류 목록은 `app_config` 의 **`db_sources`** 한 줄(쉼표로 이어 붙임)에 있습니다.
  37번이 `db_sources` **한 줄만** insert/update 를 열어 줍니다. delete 정책은
  만들지 않았고, `using`+`with check` 를 둘 다 걸어 다른 줄을 `db_sources` 로
  바꿔치기하지 못합니다. 대표 이메일·결제 설정은 그대로 대표만.
- 화면 위치
  - DB 통합 CRM → **DB 등록/수정** : 종류 칸 맨 밑 「＋ DB 종류 추가」 + 옆에 「종류 삭제」
    (`srcPick` / `srcDel` / `putSources`, 속값 `SRC_ADD='__add__'` 는 `srcSafe` 가 거릅니다)
  - DB 통합 CRM → **DB 관리** : 종류 열 · 종류 거르개 · 「DB 종류 목록」 일괄 편집칸(전원)
  - DB 통합 CRM → **KPI·타율 분석** : 「DB 종류별 타율」 표 (`srcAgg` / `srcTblHtml`)
  - APEX 앱 → **TFA 업무관리 → 오늘 터치할 사람** : 줄마다 종류 딱지 + 종류 단추
- **목록에서 지운 종류라도 이미 그걸로 저장된 DB 는 그대로 남습니다** (`srcList()` 가
  실제 자료에 있는 값을 항상 합칩니다). 지운 뒤에는 새로 고를 수만 없게 됩니다.
  지우기 전에 몇 명이 걸렸는지, 전원 화면에서 같이 사라진다는 것을 먼저 말합니다.
- 30건 못 채운 종류에는 「표본 적음」 이라고 적습니다 — 적은 수로 1등을 뽑으면 거짓말입니다.
- **종류 칸이 없는 서버에서도 안 죽습니다.** 칸 이름을 콕 집어 부르면 질의가 통째로
  거절되므로, `arLoad` 와 `saveDb` 는 거절당하면 종류를 빼고 한 번 더 부릅니다
  (`AR.noSrc`). 안 그러면 「오늘 터치할 사람」 화면 전체가 안 떴습니다.
- 검사: `scripts/check-dbsource.js` (53개)

## 고객 365일 — 누가 맡은 고객인가

지점장·대표 화면에는 팀 전체 고객이 한 덩어리로 옵니다. 그런데 목록을 부를 때
`advisor_id` 를 안 읽어서 **누구 것인지 알 방법이 없었습니다.**

- 목록 맨 위 담당자 줄 (`cmWhoChipsHtml`) — 내 것이 언제나 맨 앞, `.cm-sb.me` 로 파랗게
- 「👤 담당자로 묶기」 (`cmWhoGroupHtml`) — 가족 묶기와 **한 번에 하나만** 켜집니다
- 남이 맡은 고객 줄에만 담당자 딱지 (`.cm-wt`) — 내 것 전부에 붙으면 시끄럽습니다
- 찾기(`cmHit`)에 **담당자 이름**을 넣었습니다 — 「박서준」 이면 그 사람 고객이 나옵니다
- **실명은 그대로 이 기기 안에만** (`apex_cli_real_*`). 서버는 `김○○` 마스킹뿐이라
  팀원 고객은 마스킹으로 보이고 실명으로는 못 찾습니다. 이건 개인정보라 안 바꿨습니다.
- 검사: `scripts/check-clients.js` (담당자·검색 19개 포함)

## AI 키가 거절당했을 때

구글은 키가 틀리면 400 으로 `API key not valid. Please pass a valid API key.` 를 줍니다.
**앱이 이걸 그대로 화면에 띄우고 있었습니다** — TFA 업무관리에서도, 음성비서에서도.
`callAI` 의 「Gemini 가 죽었나」 판정에 *키 오류*가 빠져 있어서 Claude 로 넘어가지 않았습니다.

- `AI_DEAD = {gkey, gproxy, claude}` — 한 번 거절당한 통로는 **이번 접속 동안 다시 안 부릅니다.**
- 순서: 내 개인 Gemini 키가 나쁘면 → 회사 공용 통로(`/api/gemini`)로 한 번 더 →
  그것도 나쁘면 → Claude. 둘 다 나쁘면 **한국어로 무엇을 고칠지** 말합니다.
- `geminiReady()` / `claudeReady()` 가 죽은 통로를 준비된 것으로 세지 않습니다.
- 고치는 곳: Netlify 환경변수 `GEMINI_API_KEY` · `ANTHROPIC_API_KEY`
  (`nfOpenEnv()` · `nfCopyNames()` 로 바로 갑니다)
- 검사: `scripts/check-aikey.js` (13개, 구글이 주는 문장 그대로 재현)
