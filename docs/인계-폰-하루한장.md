# 하루 한 장 — 폰에서 쓰는 판 (인계)

작업 세션: `claude/yoon-brain-crm-integration-y7bdm5`
새로 들어간 것:
`app/day.html` · `app/day.webmanifest` · `scripts/check-day.js` (개인용)
`app/team.html` · `app/team.webmanifest` · `scripts/check-team.js` (팀장용)
손대지 않은 것: **`app/index.html`** · **`db-crm.html`**

---

## 1. 왜 만들었나

폰에서 고객 하나를 처리하려면 지금까지 이랬습니다.

> TFA 업무관리에서 보고 → DB 통합 CRM 을 열고 → 명단에서 찾고 → 표를 옆으로 밀어 기록

왕복이 네 번입니다. 그리고 폰에서 가로로 밀리는 표는 최악입니다 —
손가락 하나로 표를 밀다가 엉뚱한 줄에 기록이 들어갑니다.

그래서 한 장으로 합쳤습니다. **한 번에 한 사람만 세우고**, 전화하고,
돌아와서 세 번 눌러 기록합니다. 그 기록이 다음 날짜를 만들고,
그 날짜가 내일의 명단이 됩니다. 그게 캘린더입니다.

방향은 대표님이 정하신 그대로입니다.

> **핸드폰으로 편리하고 → 컴퓨터로 세밀하게 다시 한번 수정 또는 관리**

폰은 빠르게 남기는 곳, 컴퓨터는 자세히 고치는 곳입니다.
그래서 폰 화면 안에 「컴퓨터에서 마저 할 것」 칸이 따로 있습니다.

## 2. 어디로 들어가나

| 어디서 | 주소 |
|---|---|
| 폰 브라우저 (개인) | `https://<우리 주소>/app/day.html` |
| 폰 브라우저 (팀장) | `https://<우리 주소>/app/team.html` |
| 폰 홈 화면 | 위 주소를 열고 **공유 → 홈 화면에 추가** (아이폰) / **⋮ → 홈 화면에 추가** (안드로이드) |
| APEX 아이콘 길게 누르기 | 「하루 한 장 (폰)」 (안드로이드) |

**로그인은 따로 없습니다.** 같은 폰·같은 브라우저에서 APEX 를 한 번
로그인해 두면 이 화면도 바로 열립니다. 아직 로그인 전이면 화면 맨 위에
「로그인이 필요합니다」 와 **APEX 열어서 로그인** 단추가 뜹니다.
로그인 전에는 미리보기 자료로 돌고, 스스로 「미리보기」 라고 밝힙니다 —
가짜 숫자를 진짜인 척 내놓지 않습니다.

## 3. 네 판

| 판 | 하는 일 |
|---|---|
| **오늘** | 오늘 걸 사람 한 명 → 전화·문자 → 결과 세 개 중 하나 → 저장 |
| **주간** | 이번 주 일정. 약속·연락일·생일이 점으로 뜨고, 누르면 그날 목록 |
| **사람** | 내 배정 DB 전체. 이름·초성 검색, 진행중/부재/거절/미진행/계약 걸러 보기 |
| **등록** | 폰 명단에서 **고른 사람만** 내 배정 DB 로 |

### 오늘 몫은 하루치만
배정 DB 가 200건이면 「오늘 걸 사람 198명」 이 뜹니다. 그건 명단이 아니라
절망입니다. 그래서 하루 몫을 **20명**(10·20·30·50 중에 고를 수 있음)으로
끊고, 나머지는 「밀린 사람 N명은 접어 두었습니다」 로 접어 둡니다.

## 4. 누른 것이 CRM 에 그대로 들어간다

**서버 표를 새로 만들지 않았습니다. 마이그레이션도 없습니다.**
`db-crm.html` 이 이미 쓰는 표에, `db-crm.html` 이 넣는 것과 **글자 하나까지
같은 모양**으로 넣습니다. 그래서 `db-crm.html` 은 한 줄도 고칠 필요가 없었습니다.

통화를 기록하면 → `calls`

```
db_id · created_by · call_at · result · appointment_at · memo · first_call_issue
```

폰 명단에서 등록하면 → `dbs`

```
assigned_date · assigned_to · customer_name · phone · source
region · report_name · memo · created_by · updated_at
```

담당자는 나, 배정일은 오늘로 들어갑니다.
지역·메모·단계는 컴퓨터에서 마저 채우면 됩니다.

### 「상담」 은 약속 없이는 저장이 안 된다
CRM 의 `saveCall()` 이 결과가 「상담」 이면 약속 일시를 반드시 받습니다.
없으면 거부합니다. 폰에서 그걸 모르고 눌렀다가 기록이 통째로 날아가면
안 되니까, **폰에서 먼저 막고 왜 막았는지 말해 줍니다.**
날짜 한 번, 시각 한 번 — 두 번 눌러 끝납니다. 휠을 돌리지 않습니다.

### 신호가 없으면 폰에 쌓아 둔다
지하·엘리베이터에서 저장하면 폰에 쌓였다가 신호가 오면 올라갑니다.
**24시간이 넘은 것**은 저절로 올리지 않고 물어봅니다 — 하루 지난 통화가
오늘 기록으로 들어가면 안 되니까요.

### 통화 중에 화면이 꺼져도 안 날아간다
전화를 걸면 폰이 이 화면을 재웁니다. 그래서 한 글자 칠 때마다,
그리고 화면이 꺼지는 그 순간에 폰에 적어 둡니다.
`call_at` 은 **실제로 전화를 건 시각**이 들어갑니다 — 돌아와서 저장한
시각이 아닙니다.

## 4-1. 적는 이유를 바꾼다 — 지난번 말이 오늘 첫 마디가 된다

지금 메모를 적는 이유는 **관리 당하려고**입니다. 그래서 안 적습니다.
두 줄 적어 봐야 회사가 볼 뿐, 나한테 돌아오는 것이 없으니까요.

뒤집었습니다. 오늘 적은 한 줄이 **다음에 이 사람이 뜰 때 카드 맨 위에** 뜹니다.

> 🔁 **지난번 · 7월 20일 (부재)**
> 보험료가 부담된다고 하심. 지금 내는 것도 많다고
>
> **오늘 첫 마디**
> "권○○님, 지난번에 「보험료가 부담된다」 하신 것 — 그 부분부터 말씀드리려고 연락드렸습니다."
> ↳ 아래 처방전에 **「보험료」** 를 미리 넣어 두었습니다

안 적으면 다음에 내가 맨땅에서 시작합니다. **벌이 아니라 손해**라서 적게 됩니다.

메모가 없는 사람에게는 그렇다고 말하고, 왜 적어야 하는지를 알려 줍니다 —
없는 것을 지어내지 않습니다.

**화법은 여기서 만들지 않았습니다.** 지난 메모에서 낱말 하나를 뽑아
`db-crm.html` 의 처방전(`RX_LIST`)을 **대신 찾아 줍니다.** 첫 마디는
지난번 말을 되돌려 주는 **한 문장 틀**뿐입니다. 메모가 「~고 하심」 같은
기록체로 적혀 있으면 그 꼬리를 떼고 말이 되게 다듬습니다.

앱 안에서 열 때는 부모(`AR`)가 통화 메모와 전화번호를 담지 않으므로,
폰이 그 둘만 따로 한 번 더 읽어 옵니다 — `app/index.html` 은 고치지
않았습니다. **읽어 온 메모는 화면에만 쓰고 AI 로는 보내지 않습니다.**

## 5. 캘린더는 이제 진짜로 울린다

앱 전체를 뒤져 보니 `VEVENT` 가 **0건**이었습니다. 즉 지금까지
「캘린더」 는 앱 안에 그린 그림이었고, **폰이 울린 적이 없습니다.**

약속을 잡으면 그 자리에서 `.ics` 를 만듭니다.

- `DTSTART;TZID=Asia/Seoul` — 우리 시간
- `BEGIN:VALARM` / `TRIGGER:-PT60M` — **한 시간 전에 폰이 울립니다**
- 아이폰 캘린더·구글 캘린더 둘 다 그대로 들어갑니다

### 알림 — 앱을 안 열어도 그날 폰이 울린다
좋은 화면을 만들어도 폰은 **열어야** 보이는 물건입니다. 사람은 안 엽니다.
그래서 폰이 먼저 울려야 합니다. 서버도, 푸시 등록도, 앱스토어도 없이
울리게 하는 길이 하나 있습니다 — **폰 캘린더**입니다.

| 어디서 | 무엇이 |
|---|---|
| 주간 판 「이번 주 N건 담기」 | 이번 주 상담 약속 + 걸 사람 + 고객 365일 기한 + 생일 |
| 주간 판 「평일 아침마다 알려 주기」 | 평일 9시 되풀이 알림 하나 — **한 번만 담으면 됩니다** |
| 오늘 판 「오늘 N건 알림」 | 오늘치만 |
| 통화 뒤 「다음에 언제」 를 고르면 | 「🔔 그날 알림 담기」 가 그 자리에서 뜹니다 |

시각이 있는 것(상담 약속)은 **한 시간 전**, 시각이 없는 것(걸 사람·기한·생일)은
**그날 아침 9시**에 알림만 울립니다.

한 줄이 75바이트를 넘지 않게 접습니다 — 한글은 한 자에 3바이트라,
안 접으면 어떤 폰에서는 일정이 통째로 안 들어갑니다.

서버도, 대행사도, 새 표도 필요 없습니다.

## 5-1. 팀 하루 한 장 — 사업단장이 폰에서 보는 판

`app/team.html`. 개인용과 같은 얼굴이되 **색만 보라**입니다 — 내 것과 팀 것을
헷갈리면 안 되기 때문입니다.

| 판 | 하는 일 |
|---|---|
| **오늘** | 팀 합계 한 줄 · **아직 0통인 사람** · 몇 시에 걸고 있나(8→21시) · 많이 돈 사람 |
| **팀원** | 사람마다 오늘/이번 주. 누르면 첫 통화·마지막 통화·부재·배정 DB·잡힌 상담 |
| **피드백** | AI 가 **전체 한 줄 + 사람별 한 줄**을 씁니다 |

### 새 표를 만들지 않았습니다
`calls` 와 `dbs` 를 사람별로 **세기만** 합니다. 팀원이 폰에서 남긴 통화가
그대로 여기 올라옵니다 — 그래서 숫자가 어긋날 수 없습니다.

누구를 볼 것인가는 조직도를 그대로 따릅니다.
`teams.leader_id = 나` 인 팀의 `team_members`. 역할이
`admin·owner·master·hq·branch_manager` 면 전체. 둘 다 아니면
「팀장 화면입니다」 라고 말하고 조직도로 보냅니다.

### AI 로 나가는 것 — 여기가 제일 중요합니다
**팀원 이름과 숫자뿐입니다.** 고객 이름·전화번호·통화 메모는 한 글자도
보내지 않습니다. 무엇이 나가는지는 화면에서 **직접 열어 볼 수 있습니다**
(피드백 판 → 「AI 에게 무엇을 보내나 · 열어 보기」). 검사에서도 그것을 봅니다.

AI 를 부르는 길은 둘입니다.
앱 안이면 앱이 쓰던 `callAI()` 를 그대로 씁니다 — 한도·대체·기록이 전부 앱 것입니다.
앱 밖(폰 홈 화면)이면 **회사 공용 Gemini 중계**(`apex_studio_gproxy`)만 씁니다.
개인 API 키는 만지지 않습니다. 둘 다 없으면 없다고 말하고 APEX 로 보냅니다.

### AI 가 팀원에게 직접 보내지 않습니다
**대표님이 읽고, 고쳐서, 복사해서** 보냅니다. 그래서 「복사」 입니다 —
자동으로 나가면 어느 날 엉뚱한 말이 나갑니다.

- 「전체 복사」 → 단톡방에 그대로
- 사람마다 「📋 복사」 → 1:1 로
- 「사람별 전체 복사」 → 한꺼번에

오늘 쓴 것은 `saved_reports(kind='team_feedback')` 에 **하루 한 줄**로 남습니다.
다시 쓰면 새 줄이 아니라 그 줄을 고칩니다. 새 표도, SQL 도 필요 없습니다.

### 왜 팀원 폰으로 바로 쏘지 않았나
`daily_checks` 는 쓰기 정책이 `member_id = auth.uid()` 라 **리더가 팀원 행에
쓸 수 없고**, `saved_reports` 는 읽기 정책이 `advisor_id = auth.uid() or
is_admin()` 이라 **팀원이 리더 줄을 읽을 수 없습니다.**
리더 → 팀원으로 바로 꽂으려면 새 표와 새 RLS 가 필요합니다. 그건 SQL 을
다시 돌려야 하는 일이라 하지 않았습니다. 필요하시면 그때 따로 올리겠습니다.
지금은 카톡·문자가 더 빠르고, 대표님이 한 번 읽고 나간다는 점이 오히려 낫습니다.

## 6. 넘지 않은 두 개의 선

`docs/인계-고객관리와폰.md` (고객관리 세션) 에서 그은 선을 그대로 지켰습니다.

**(1) 「무엇을 언제 해야 하는가」 는 건드리지 않았습니다.**
3년 규칙·연차별 관리 주기는 고객관리 세션 것입니다. 여기서 다시 만들지
않았습니다. 처음에 폰 화면에 넣었던 「부재 3일 뒤·거절 30일 뒤」 같은
**지어낸 주기는 전부 지웠습니다.** 지금 다음 연락일은 두 가지에서만 옵니다.

```js
function nextOf(r, v){
  if (v.next[r.id]) return v.next[r.id];       /* 사람이 직접 고른 날 */
  if (r.appt)       return r.appt.slice(0,10); /* 잡힌 상담 약속 */
  return '';                                   /* 미정 — 지어내지 않는다 */
}
```

우리 쪽은 「그걸 **어디서 보고 어떻게 누르는가**」 (폰 모드·캘린더·알람)
만 합니다.

**(2) `app/index.html` 은 한 글자도 고치지 않았습니다.**
그래서 `APP_BUILD` 도 그대로입니다 — 세션끼리 부딪히는 자리가 없습니다.
`db-crm.html` 도 읽기만 했습니다. 거기 이미 들어간 두 기능
(**고객 처방전 `RX_LIST`**, **문자 `smsBody`**) 은 지우지 않고 **그대로 씁니다.**

- 문자 문구는 `db-crm.html` 의 `smsBody()` 와 같은 말입니다.
- 처방전은 폰이 `db-crm.html` 을 읽어 **`RX_LIST` 를 그대로 가져옵니다.**
  대표님이 `db-crm.html` 의 `RX_LIST` 한 곳만 고치시면 **폰도 같이 바뀝니다.**
  (`RX_LIST` 가 아직 main 에 없으면 폰은 「앱 안에서 뜹니다」 라고
  솔직히 말하고 넘어갑니다 — 없는 것을 지어내지 않습니다.)

## 7. 앱 안에 넣을 때 (아직 안 넣었습니다)

`app/index.html` 을 고치는 것은 다른 세션과 부딪히는 자리라 손대지
않았습니다. 넣으실 분은 **DB 통합 CRM 을 붙인 방식 그대로** 하시면 됩니다
— 네 군데입니다.

```html
<!-- (1) 자리 하나. crmFrame 옆에 그대로 흉내 낸다.
         sandbox 는 붙이지 마십시오 — 문자(sms:)·전화(tel:)·캘린더 내려받기가 막힙니다 -->
<iframe id="dayFrame" title="하루 한 장"></iframe>
```

```js
/* (2) 여는 함수. mountCrm() 과 같은 모양이다 */
function mountDay(){
  var f=$('dayFrame'); if(!f||f._mounted)return;
  f.src='day.html?v='+encodeURIComponent(APP_BUILD); f._mounted=true;
}

/* (3) go() 안에 한 갈래 */
if(tab==='day'){
  mountDay(); osFullMode('day-mode'); navMark('day');
  if(window.innerWidth<=880){$('sidebar').classList.remove('open');$('scrim').classList.remove('on');}
  return;
}
```

```js
/* (4) TABS 의 「하루 시작」 묶음에 한 칸 */
{id:'day', icon:'📱', title:'하루 한 장 (폰)'}
```

`?v=`+`APP_BUILD` 를 꼭 붙이십시오. 안 붙이면 브라우저가 지난번에 받아 둔
화면을 그대로 다시 씁니다 — CRM 에서 이미 한 번 겪은 일입니다.

폰 화면은 부모가 있으면 **부모의 서버 연결(`osClient()`)과 `AR` 자료를
그대로 씁니다.** 새로 붙지 않습니다. 부모가 없으면(홈 화면에서 바로 열면)
혼자 붙습니다. 어느 쪽이든 같은 화면입니다.

## 8. 검사

```
node scripts/check-day.js     # 개인용 · 63가지
node scripts/check-team.js    # 팀장용 · 26가지
```

`check-day.js` 가 보는 것:

- 네 판이 오류 없이 열리는가
- 「상담」 인데 약속이 없으면 저장이 막히는가
- 저장하는 한 줄이 `saveCall()` · `saveDb()` 와 **같은 칸 이름**인가
- `.ics` 에 `VEVENT` · `VALARM` · `TZID=Asia/Seoul` · CRLF 가 있는가
- 문자가 본인 폰의 문자앱으로 열리고, 문구가 CRM 과 같은 말인가
- 고른 사람만 들어가는가 (안 고르면 잠긴다)
- 로그인 전에 「미리보기」 라고 스스로 밝히는가
- 지난번에 들은 말이 오늘 첫 마디로 돌아오는가 · 메모가 없으면 없다고 말하는가
- 이번 주 알림이 한 파일에 담기고, 모든 일정에 알람이 붙는가
- 캘린더 한 줄이 75바이트를 넘지 않는가

`check-team.js` 가 보는 것:

- 세 판이 오류 없이 열리는가 · 아직 0통인 사람이 따로 서는가
- **AI 에게 보내는 글에 고객 이름·번호·메모가 없는가** (가장 중요)
- AI 가 전체 한 줄과 사람별 한 줄을 만드는가
- 리더가 읽고 **복사해서** 보내는가 — AI 가 직접 보내지 않는가
- AI 가 없는 폰에서 「없다」 고 말하는가 — 조용히 아무것도 안 하지 않는가

`.github/workflows/check.yml` 에 들어 있어 PR 마다 돕니다.
