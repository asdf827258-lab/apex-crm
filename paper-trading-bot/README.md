# paper-trading-bot

Alpaca 5자산·3전략 자동매매 봇. **기본값은 모의투자(paper)** 이고, 실계좌는
세 가지 열쇠가 동시에 있을 때만 열립니다.

이 봇은 돈을 벌어주는 물건이 아니라 **규칙을 사람 대신 어기지 않고 지켜주는**
물건입니다. 그래서 이 문서에서 가장 긴 부분은 전략이 아니라 안전장치입니다.

## 3. 거래 대상과 전략

| 자산 | 전략 | 봉 | 규칙 |
|---|---|---|---|
| SPY | 평균 회귀 | 15분 | 20기간 평균에서 ±1.5σ 벗어나면 진입, 평균 복귀 시 청산 |
| QQQ | 평균 회귀 | 15분 | 같은 규칙, ±1.8σ (변동성이 커서 기준을 넓게) |
| BTC/USD | 돌파 | 1시간 | 직전 20봉 고점 돌파 + 거래량 20봉 평균의 1.5배 |
| GLD | 추세 추종 | 4시간 | 50 EMA 가 200 EMA 를 교차하는 **순간** |
| USO | 추세 추종 | 4시간 | 같은 규칙 |

> ### ⚠️ GLD·USO 는 금·원유가 아닙니다
>
> 둘 다 **ETF 대리 자산(proxy)** 입니다. 원자재 선물이 아닙니다.
>
> - **GLD** 는 금 현물을 보관하는 신탁이라 금 가격을 비교적 가깝게 따라가지만,
>   연 0.4% 수준의 보수가 계속 빠져나갑니다.
> - **USO** 는 WTI 원유 **선물**을 굴리는 ETF입니다. 만기마다 다음 달 선물로
>   갈아타는데(롤오버), 원월물이 더 비싼 콘탱고 국면에서는 **유가가 제자리여도
>   ETF 가격은 계속 깎입니다.** 2020년에 실제로 액면 병합까지 갔습니다.
>
> 즉 "원유가 오를 것 같다" 와 "USO 가 오를 것 같다" 는 같은 문장이 아닙니다.
> 백테스트 성과를 원자재 성과로 읽지 마세요.

전략 파라미터는 코드가 아니라 `config.yaml` 에서 고칩니다. 값을 바꿨으면
**백테스트부터 다시 돌리세요.**

## 4. 안전장치 — 이 프로젝트의 본체

### ① 실계좌 3중 잠금

세 가지가 **동시에** 있을 때만 실계좌가 열립니다. 하나라도 빠지면 조용히
실패하지 않고 **모의로 내려간 뒤 무엇이 빠졌는지 알려줍니다.**

| 열쇠 | 어디에 |
|---|---|
| ① `ALPACA_PAPER=false` | `.env` |
| ② `ALPACA_LIVE_CONFIRM=I_UNDERSTAND_REAL_MONEY` | `.env` (오타 나면 안 열립니다) |
| ③ `--live` | 명령줄 |

`tests/test_live_requires_triple_confirm.py` 가 2×2×2 = 8가지 조합을 모두 돌려
**정확히 한 조합만 실계좌로 열리는지** 확인합니다.

실계좌가 열리면 주문 전에 배너가 뜨고 10초를 셉니다 — 잔고, 한 번에 잃을 수
있는 최대 금액, 접속 주소를 보여주고, 그동안 Ctrl+C 로 멈출 수 있습니다.

### ② 거래당 1% — 손절 폭이 수량을 정한다

수량을 먼저 정하고 손절을 맞추는 게 아니라, **손절 폭에서 수량이 나옵니다.**

```
수량 = (잔고 × 1%) ÷ |진입가 − 손절가|
```

그래서 조용한 금이든 요동치는 비트코인이든, 한 번 틀렸을 때 잃는 돈은 똑같이
잔고의 1% 입니다. 손절가는 ATR 배수로 잡습니다.

- 손절 거리가 0 이면 **주문하지 않습니다** (0으로 나누면 수량이 무한대가 됩니다)
- 손절이 너무 좁아 수량이 잔고를 넘으면 잔고 기준으로 깎습니다
- BTC 만 소수 수량, 나머지는 정수로 내림

### ③ 상관 필터

SPY 와 QQQ 가 **둘 다 롱**이면 BTC 신규 롱을 막습니다. 셋이 같은 방향으로
움직이는 날 위험이 3배가 되기 때문입니다.

백테스트 결과의 `blocked_by_correlation` 이 실제 차단 횟수입니다. **0 이면
필터가 켜져 있으나 마나라는 뜻**이니 그 숫자를 보세요.

### ④ 낙폭 10% 자동 정지

잔고 최고점 대비 10% 빠지면 **주문을 취소하고 전량 정리한 뒤 STOPPED** 로
바꿉니다. 잔고가 회복돼도 **자동으로 풀리지 않습니다.** 사람이 직접
`python main.py resume` 을 쳐야 합니다.

재개해도 **잔고 최고점을 낮추지 않습니다.** 낮추면 같은 손실을 한 번 더
허용하게 되기 때문입니다.

최고점은 `state.json` 에 저장됩니다. 저장하지 않으면 껐다 켤 때마다 기준이
초기화돼 정지 장치가 무력해집니다.

### ⑤ 키는 어디에도 찍히지 않는다

- 키는 `.env` 에서만 읽습니다
- 화면에는 앞 4글자만 (`PKAB…`) 나옵니다
- 리포트를 내보내기 직전 `scrub()` 이 본문을 한 번 더 훑습니다 (있으면 안 되지만,
  한 번 새면 회수할 수 없어서 그물을 두 겹 둡니다)

## 5. 백테스트 — 스스로를 속이지 않기 위한 장치

백테스트를 실제보다 좋게 보이게 만드는 반칙 세 가지를 코드에서 막습니다.

| 반칙 | 이 프로젝트의 처리 |
|---|---|
| 신호 난 봉의 **종가로 체결** | **다음 봉 시가**로 체결합니다. 그 종가를 보고 나서야 주문할 수 있으니까요. 마지막 봉에서는 아예 진입하지 않습니다(다음 봉이 없으므로). |
| 수수료·슬리피지 **0** | 항상 반영하고, 결과 맨 위에 가정값을 같이 찍습니다. `--slippage-bps 10` 으로 올려보세요. |
| **미래 참조** | 지표는 `shift(1)` 로 과거만 보고, 루프도 i 시점까지만 읽습니다. |
| **봉 안쪽** 미래 참조 | 트레일링 스톱은 '들고 들어온 값' 으로 판정하고, 살아남은 뒤에 올립니다. |
| 진입 수수료 누락 | 왕복(진입+청산) 수수료를 거래 손익에 넣습니다. |
| 종목을 하나씩 끝까지 | 전 종목을 **시간 순으로 섞어서** 돌립니다. |

`tests/test_no_lookahead.py` 가 **뒤쪽 데이터를 3배로 왜곡한 뒤 앞쪽 지표가
바뀌는지** 봅니다. 바뀌면 미래를 본 것입니다.

### 실제로 잡힌 버그 네 개

단위 테스트가 초록불인 채로 기능이 죽어 있을 수 있습니다. 넷 다 그랬습니다.

1. **추세추종의 교차 판정이 통째로 죽어 있었습니다.** `shift(1)` 을 `fill_value`
   없이 쓰면 dtype 이 object 가 되고, `~prev` 가 `-1`/`-2` (둘 다 참) 이 되어
   마스크가 사라집니다. "교차한 순간"이 아니라 **"위에 있는 모든 봉"** 이 매수
   신호였습니다 — 600봉 중 85봉 전부.

2. **트레일링 스톱이 봉 안쪽을 훔쳐봤습니다.** 이번 봉 고가로 스톱을 올린 뒤
   이번 봉 저가로 손절을 판정했습니다. 봉 안에서 고가와 저가 중 뭐가 먼저였는지는
   알 수 없는데, 유리한 쪽으로 가정한 것입니다. 진입가 100·스톱 90 인 포지션이
   고가 130·저가 95 인 봉에서 **"손절"인데 주당 +15 이익**으로 청산됐습니다.

3. **상관 필터가 한 번도 막지 못했습니다.** 종목을 하나씩 끝까지 돌리니 BTC
   차례에는 SPY 를 이미 다 팔고 난 뒤였습니다. **3,433번 호출 · 0번 차단.**
   `test_risk.py` 는 함수를 따로 불러 검사해서 통과하고 있었습니다.

4. **진입 수수료가 거래 손익에서 빠져 있었습니다.** `trades.csv` 가 비용을
   절반만 보여줬습니다.

②③④를 고치자 합성 데이터 백테스트 손익이 **-68,115 → -79,716** 으로 나빠졌습니다.
없던 이익 약 11,600 이 사라진 것입니다. `tests/test_backtest_integrity.py` 가
이 넷을 전부 붙잡아 둡니다 — 고치기 전 코드에 돌리면 실패하는 것을 확인했습니다.

### 실행

```zsh
python main.py backtest --months 6
python main.py backtest --months 6 --slippage-bps 10     # 비용을 올려서 견디는지
python main.py backtest --months 6 --synthetic           # 키 없이 배관만 확인
```

`results/` 에 `trades.csv` · `daily_pnl.csv` · `equity_curve.csv` ·
`backtest_results.png` · `summary.json` 이 남습니다.

### 다음 단계로 갈지 판단하는 기준

결과 맨 아래에 체크리스트가 나옵니다. **하나라도 ❌ 면 모의투자로 넘어가지 마세요.**

- 거래가 실제로 발생했는가 (0건이면 규칙이 너무 빡빡한 것)
- 최대 낙폭 15% 이하
- 샤프 지수 양수
- 비용이 0 이 아닌가
- 한 자산이 수익의 80% 를 넘지 않는가 (넘으면 나머지 4개는 장식입니다)

`--synthetic` 결과는 **성과로 읽으면 안 됩니다.** 합성 데이터는 순수한
랜덤워크라 평균회귀 전략이 비용만큼 손해 보는 게 정상입니다. 실제로 그렇게
나옵니다 — 그게 백테스트가 스스로를 속이고 있지 않다는 증거입니다.

아침(기본 07시)엔 어제 성과와 오늘 감시 대상을, 저녁(21시)엔 오늘 체결·손익·

## 9. 실계좌로 넘어가기 전에

이 순서를 건너뛰지 마세요. 각 단계는 앞 단계가 통과했을 때만 의미가 있습니다.

1. `pytest -q` 전부 통과
2. `backtest --months 6` 체크리스트 5개 전부 ✅
3. `backtest --slippage-bps 10` 으로도 살아남는지 — 비용에 예민하면 실전에서 죽습니다
4. `paper --dry-run` 으로 계획이 상식적인지 눈으로 확인
5. **모의계좌로 최소 2~3개월** 실제로 돌려보기
6. 그 결과가 백테스트와 크게 다르지 않은지 비교
7. 그 다음에야 실계좌 이야기를 꺼냅니다. 처음엔 잃어도 되는 금액으로만.

### 이 봇이 하지 않는 것

- 시장을 예측하지 않습니다. 정해진 규칙을 지킬 뿐입니다.
- 손실을 막아주지 않습니다. 손실의 **크기를 정해둘** 뿐입니다.
- 남의 돈을 굴리는 용도가 아닙니다. 국내에서 타인 자금을 일임 운용하려면
  투자일임업 등록이 필요합니다.

과거에 통했다고 앞으로 통한다는 보장은 없습니다.
